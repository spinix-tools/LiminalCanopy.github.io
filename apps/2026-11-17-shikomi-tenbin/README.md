# 仕込みの天秤 / SHIKOMI TENBIN ⚖

2026-11-17に制作した、マルシェ・単発催事・キッチンカーの小規模食品出店向けWebアプリMVP。

**使い方：** `index.html` をブラウザで開き、イベント固定費・使える仕込み時間・各商品原価と需要を入力するだけ。HTML内にCSS/JSを内蔵した単一ファイルで、外部ライブラリ、サーバーAPI、ログイン、追加課金は不要。通常のWebブラウザではデータをlocalStorageに自動保存し、JSON入出力とCSV書き出しにも対応します。

## 誰の課題を解くか・需要仮説

週末マルシェ・単発イベントでの仕込み数は、売り切れによる販売機会の損失と売れ残りロスを同時に抱える。商品ごとの適当な「持込数」を出すだけでなく、**限られた仕込み時間を複数商品で取り合う条件で、利益が最大の仕込み数の組合せを選ぶ**ことに絞る。実ユーザーによる課題深度や支払い意向の検証は未実施。

## 実装

- 商品1〜6種類（価格・原価・残品回収価値・1個の仕込み分数・少なめ／通常／多め需要）
- 出店料・交通費・その他固定費、仕込み時間上限0〜900分
- 需要シナリオ3本と確率（合計100%）をユーザーが入力
- 通常＝入力確率で最適化、慎重＝60/30/10、強気＝10/25/65で仕込み数を選ぶ。各方針の利益比較は**入力した確率**で統一
- 商品横断の共有時間制約で整数個数を多重選択ナップサックDPにより**厳密最適化**（近似ではない）
- 赤字シナリオ確率、売れ残り・未販売期待個数、シナリオ利益、各商品の推奨仕込み数
- localStorageの自動保存、JSONエクスポート／インポート、BOM付きCSV、計画のコピー／印刷
- JSONは上限100KBとスキーマ検査、表示文字列はHTMLエスケープ、CSVの式注入対策あり

### 計算式

シナリオ `s`、商品 `i` の仕込み個数 `q_i` と需要 `d_is` について、

`利益_s = Σ_i [販売価格_i × min(q_i,d_is) + 回収価値_i × max(q_i−d_is,0) − 原価_i × q_i] − 固定費`

`期待利益 = Σ_s [入力確率_s × 利益_s]`

`Σ_i (仕込み分/個)_i × q_i ≤ 仕込み上限分` を満たす整数 `q_i` を探索。各 `q_i` は多め需要以下（回収価値は原価以下）。利益が同点の場合は総仕込み時間の少ない解を選ぶ。

**前提と限界：** 需要や確率は予測されたものではなく、入力者の仮定。赤字確率も3シナリオについて計算したものに限る。原価は売れなかった個数を含む全仕込みに課す。税・手数料・人件費・売れ残り回収可能性・設備制約・食品衛生は未モデル化。出店料など固定費は仕込み0個でも控除。最適化は仕込み時間という単一の制約についてのみ保証。現実の利益やロス低減を保証しない。
