# TurnWindow / 譜めくり計画（MVP）
2026-11-29 | 対象：室内楽・合奏の演奏者、編曲者、楽譜制作担当者。

## 選定理由と差別化仮説
日本語版MuseScoreのマニュアルには段数・改ページの手動調整があり、LilyPondは休止区間を考慮する自動改ページを備える。課題の存在は確認できるが、市場規模・支払意思は未検証。既存の高機能な記譜ソフトと競うのではなく、共通の段境界を使う複数奏者の空き時間を同時評価し、最大段数による配置との比較・不足内訳を出す独立した軽量ツールを仮説とする。
- 日本: https://musescore.org/ja/print/book/export/html/329597
- 海外: https://lilypond.org/doc/v2.26/Documentation/notation/page-breaking
- 重複確認: 直近の会話履歴、mainとの比較で取得した300ファイル（51アプリディレクトリ）、page turn / 譜めくり / 楽譜 / PageTurn のコミット検索（各0件）。全ソースの網羅照合ではない。

## 使い方
index.htmlをブラウザで開く。各段の終わりの連続空き時間（秒）を奏者ごとにカンマ区切りで入力（1〜200段、1〜8人）。必要秒数、段数上下限、全/奇数/偶数ページのめくり方式を選択して計算。JSONで計画保存。最終ページでは最小段数を適用せず、終段に譜めくりはない。秒数はミリ秒整数に変換。動的計画法で不足する奏者×回数、不足時間、ページ数、空き段数二乗和の順に辞書式最小化。

## 検証
- node test.cjs: 独立全列挙との400ケース照合、固定8アサーション合格。200段・8人も確認。
- python test_browser.py: Chromiumで同一HTMLをインライン読込（環境のfile://制限）、JSONダウンロードと内容、入力変更後の無効化、時間不足、奇数ページ、不正行、390px幅を確認。JS例外・外部HTTP要求0件。ブラウザテストにはPlaywrightとChromiumが必要。
- サンプル（12段・2人・必要2秒・最大5段）: 5/10段後の不足4人×回・計6秒から、3/7段後の不足0へ改善。3ページを維持。
- 実際の楽譜データ、段の物理高さ、運指、反復、印刷、他ブラウザ、実演での検証は未実施。休止を自動推定せず、楽譜の直接編集はしない。安全な譜めくりを保証するものではない。
- 外部API・依存ライブラリ・分析タグ・登録・永続的な入力保存なし。追加有料サービス利用なし。入力は端末内のみ。
