# 列こま / RETSUKOMA — 開催前の行列・人員配置シミュレーター

2026-11-17 作成。登録不要・通信不要の単一 HTML Web アプリ。`index.html` を開けば操作可能です。MIT ライセンス。

## 対象と選定理由
地域イベント、校内催事、ポップアップ店舗、小規模な受付・販売ブースの運営者。時間帯によって来客が偏り、何人の受付担当が必要かを事前に判断したい小規模組織を想定。日本の Airウェイトと Junban は順番受付・呼出・実績管理のサービスを提供。海外の Waitwhile・Qminder も受付/待ち時間/要員配置を扱う。一方、QueueSim や MySolvers のような**無料シミュレーターも既存**であり、シミュレーション自体は新規ではない。

## 差別化仮説（未検証）
**日本語・無登録・顧客情報ゼロで、30分ごとの来客数とスタッフ数を入れるだけで P90 待ち時間を比較し、同じ乱数を利用した近似的な追加配置案、CSVでの共有まで完結**させる。多機能な受付管理や汎用待ち行列ソルバーに比べ、単発イベントの事前打ち合わせで価値を出す仮説。利用者需要・収益性の実測はまだない。

## 実装機能
- 6枠×30分の到着組数・担当人数、接客平均・変動係数・目標P90・試行回数・乱数シードを設定
- 非定常ポアソン来客、対数正規の接客所要時間、FIFOを想定した離散イベント試算（20〜200回）
- P90・平均待ち時間・目標以内率・最大待機列・総来客・担当人時・時間帯別 SVG グラフ
- 追加人員を最大6人枠、各枠最大9人で貪欲探索して、同一シードで現在/改善案を比較
- CSV結果出力、設定JSONの出力・復元、端末内localStorage保存、印刷、レスポンシブ表示
- 外部API/ライブラリ/有料サービス/顧客情報の取得なし

## 実行とテスト
`index.html` をブラウザで開く。Node.js 22 で `node engine.test.cjs`、Python + Playwright + Chromium で `python browser_test.py`。

- Node 単体: **31/31 合格**。入力境界、乱数再現性、ゼロ来客、スタッフ交代、負荷と待ち時間、配置最適化の上限を確認。
- Chromium UI: **27/27 合格**。編集→再試算、提案比較、グラフ、CSV/JSONダウンロード・復元、エラー、保存書込、スマホ幅を確認。
- 試験環境では `file://` のナビゲーションが管理ポリシーでブロックされたため、実 HTML/JS を `page.set_content()` で読み込み、`localStorage` を試験用モックで再現。**実配信URL・実端末での保存持続性は未検証**。
- 試算値は仮定モデルに依存し、待ち行列の離脱、複数工程、複数列の合流、休憩時の中断、会場安全・収益への影響は未実装。最適配置の保証もない。
