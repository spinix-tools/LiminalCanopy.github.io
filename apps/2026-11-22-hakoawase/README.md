# 箱あわせ / HAKOAWASE — 箱選びに、勘だけを使わない。

**2026-11-22 MVP / オフラインWebアプリ** — `index.html` をブラウザで開く（または静的ホスティング）。外部API、アカウント、サーバー、追加課金不要。

## ターゲットと選定理由
日本の小規模EC事業者、ハンドメイド商品発送者、マルシェ出店者。2026年10月21日公表の経産省調査によると2025年の国内BtoC-EC市場は27兆5,580億円、うち物販系15兆8,233億円。国交省の2026年11月13日発表では2025年度宅配便取扱個数は51億6,178万個（前年比約2.5%増）。これはアプリ需要の実測値ではなく、梱包業務の周辺市場データ。

海外でもJETRO『世界貿易投資報告2026』は2025年の世界EC小売市場を6兆4,657億米ドル（eMarketer推計）と紹介している。小規模な出荷担当者が「手元の箱のどれを使えばよいか」をすぐ試せることを狙う。

## 競合と差別化仮説
- **国内・日本語**：TETRA / PACKWISE（iOS、2026年11月確認）は商品の寸法・数量、箱の選択、3Dの詰め順やオフライン利用に対応する。近接競合であり、本企画だけが箱詰めを可能にするわけではない。
- **海外**：3DBinPacking.com は本格的な箱サイズ比較と配置最適化、Binacle.Net はセルフホスト型3D梱包APIを提供する。
- **仮説**：アカウント不要の静的ページで **商品ごと一律の6面緩衝余白、箱の調達単価での候補順位、非配置品の明示、配置座標CSV** を一画面で使えると、少量多品種の発送前チェックに価値がある。ただし、競合に対する優位性、利用継続率、課金可能性は未検証。

## 実装した機能
商品名・寸法（cm）・数量・天地固定を入力、箱の内寸・単価を最大12種類比較。緩衝余白（各面0〜3cm）を加えた直方体を4種類の並べ順で探索し、収納可能な候補を箱の単価順で表示。部分的にしか収まらない候補と未配置品を表示。立体模式図、詰め順スライダー、JSON設定の入出力、配置CSV出力、端末内保存、印刷に対応。商品最大16種類・合計24個。上限と正の寸法を検査する。

`engine.js` は自由空間を分割して直方体を置くヒューリスティック。**最小箱・必ず入る/入らない・運賃・重量制限・耐荷重・保護性能は保証しない**。"入る" は数理モデルにおける非重複配置候補、"入らない" は探索で配置を発見できなかった意味。箱は実際の内寸で測定し、現物で確認すること。緩衝材は矩形余白による簡略モデルで、梱包の安全性を判定しない。商品情報の外部送信なし。

## テストと制限
- `node --test engine.test.cjs`：**18/18 合格**。既知の配置・回転制限・費用順位・エラー、シード固定の**600条件**で、境界内・重複なし・個数保存を検査。
- `python browser_test.py`：Chromiumで**33/33 操作検査に合格**。商品追加/削除、再計算、手順、JSON/CSV、ヘルプ、画面幅、例外なし、外部通信なし。
- 管理環境では `file://` とローカルURLへのChromium直接アクセスが `ERR_BLOCKED_BY_ADMINISTRATOR` で遮断された。**操作テストは同一 HTML/CSS/JS をインライン展開したDOMで実施し、端末保存はlocalStorageの模擬実装で検証した**。通常のローカルファイル直接起動・長期保存は未検証。
- 自動梱包アルゴリズムは全探索ではなくヒューリスティックである。実際の荷物での精度調査や顧客インタビューは行っていない。

## ソースと実行
`index.html`, `style.css`, `engine.js`, `app.js` が本体。テスト `engine.test.cjs`, `browser_test.py`。純粋なフロントエンド。GitHub版は保存時にファイル分割/配布形態が異なる場合があり、完全な可読ソースは配布ZIPに含む。
