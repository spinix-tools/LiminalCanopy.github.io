# つりかご / TSURIKAGO

学園祭・マルシェ・バザーの準備担当者向け、**日本円の釣銭準備・不足リスクのローカルシミュレーター**。インストール・登録・APIキー不要。`index.html` をブラウザで開くだけで使えます（`engine.js` / `app.js` / `style.css` と同じディレクトリに配置）。

## 今回選んだ理由と競合（調査日：2026-11-18）

- **国内需要の周辺指標：** 経産省は2026-03-31に、2025年のキャッシュレス決済比率を新しい**国内金額ベース指標で58.0%**と発表した。これは現金決済「件数」の割合を直接示すものではない。現金を扱う小規模催事での事前準備という用途を狙う。出典: https://www.meti.go.jp/press/2025/03/20260331006/20260331006.html
- **国内競合：** [i金種計算機](https://apps.apple.com/jp/app/id375352735) は金種別集計、[お釣り 電卓](https://apps.apple.com/jp/app/id367338685) は屋台等の釣銭計算を提供。
- **海外競合：** [TillClosr Starting Cash Bank Float Calculator](https://tillclosr.com/tools/starting-bank-float/) は予想現金取引数と平均釣銭から開始釣銭を提案し、[Till Counter](https://www.tillcounter.app/) は金種別の現金集計、[Cash Register Event Simulator (Goalino)](https://apps.apple.com/us/app/id6758986207) は催事向け現金会計練習を提供。
- **差別化の検証仮説：** 「日本円の具体的な商品価格 × お客の額面別支払傾向 × 持参する金種枚数」の**繰返し取引シナリオ**で不足の再現可能な危険度を示し、予算内の**単一補充パック**を比較する。競合に同等機能が全くないとの主張ではない。独自の有料化需要は未検証。

## 操作できるMVP

商品名・価格・販売比率の編集（20種まで）／紙幣・硬貨9金種の枚数編集／支払傾向（ちょうど、1,000円、5,000円、10,000円）／擬似乱数シード固定の繰り返し試算（最大250件 × 300回）／釣銭を実在庫内で組む **bounded change-making**／完走率・平均対応件数・初回シナリオログ／予算内の追加パック単独比較／チェックリストCSV・設定JSON出力入出力／localStorageで端末内保存／印刷／スマホ対応。

`index.html` はローカルファイルで利用可能。HTTPサーバーを使う場合は、このフォルダで `python -m http.server 8000` を起動。

## 判定モデルと限界

1. 1取引で商品1種類のみ。商品の販売比率に応じて抽選し、支払額面を比率で抽選。商品価格を下回る額面は候補から除外し、全候補がなくなれば「ちょうど」で支払う仮定。ちょうど支払いは大きい金種から分解して受け取ったものとする。
2. 受取現金を引出しに追加後、在庫数の範囲で釣銭を構成（貪欲法を先に試し、失敗時はメモ化探索で別構成を探す）。釣銭が作れなければその回はそこで停止。入出金管理・税額計算・レシート・両替手数料は対象外。
3. 完走率は**入力した販売・支払モデルとシード集合に依存する参考値**。経営上の損失確率や実際の顧客行動を推定したものではない。2,000円札は対象外。
4. 補充案は予算内で7金種の固定パックを**各1種類だけ**追加して比較。複数パックの最適化、金融機関の両替在庫、追加コストは考慮しない。
5. 個人情報・秘密情報を要求せず、ネットワーク通信や外部APIなし。設定は端末内に保存（ブラウザが許可する場合）。会計・監査・法令順守を保証するレジではない。

## テスト結果（2026-11-18）

- `node --test engine.test.cjs` : **27 / 27 合格**。釣銭の保存則・枚数上限・不足・乱数再現性・入力検証・補充予算を検査。
- `python browser_test.py` : **27 / 27 合格**（Chromium 画面操作）。商品追加編集削除、金種編集、再試算、補充比較、CSV・JSON出力、JSON読込、モバイル表示など。
- **テスト環境上の制約：** ブラウザの `file://` 遷移が管理者制限で拒否されたため、実ファイルのHTML/CSS/JSを `page.set_content` / `add_style_tag` / `add_script_tag` で直接配置した。`localStorage` はモックで再初期化時の値引継ぎを試験。実ファイルURLでの直接起動、実Web配信、ブラウザ本来の永続保存、印刷実機は未検証。
