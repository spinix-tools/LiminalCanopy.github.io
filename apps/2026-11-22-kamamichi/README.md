# 窯みち / KAMAMICHI — ベーカリー焼成段取りシミュレーター

2026-11-22 / Hourly App Lab / MIT / 外部API・課金・アカウント・個人情報収集なし

## 誰に・なぜ

対象は、仕込み台が1つ・共用窯が1つ程度の小規模ベーカリー、製パン教室、少人数製造チーム。朝の複数バッチについて「焼き上がり時刻だけを並べても、窯の天板が重複する」「生地が発酵上限を超える」といった段取り上の詰まりを事前に発見したい人を想定。

日本市場の間接シグナル：矢野経済研究所が **2026-09-17** に公表した調査では2025年度の国内業務用主要製パン材料市場が**3,358億4,000万円**で、人手不足と作業省力化が課題として挙げられている。ただし材料市場の規模は本アプリの市場規模を意味しない。国内競合 **Bakery MiniOn** はレシピ管理・製パン支援を展開、**a tempo** はベーカリーの時間別生産計画を訴求している。海外では **CoreBake** が発酵を含むライブタイムライン、**Recipok** が窯の段数・焼成計画、**BakeIQ** が製造予定とレシピ・受注を統合。すでに強い既存製品がある。

**差別化仮説**：高機能なERPやレシピ管理を導入する前に、当日分の「仕込み1系統→発酵許容窓→窯の有限天板数→冷却→完成期限」だけを5分粒度で試せる、アカウント不要の小さな診断器に需要がある。`窯+1枚`のwhat-if比較を同画面に出す。価格・収益性・顧客需要は未検証。追加の有料サービスやOpenAI APIは使用しない。

## 実装と使い方

`index.html` を開く（`style.css`、`engine.js`、`app.js` と同一フォルダ）。初期デモ6バッチは自由に書き換え可能。開始時刻と窯の天板容量、製品ごとの必要天板、仕込み分数、発酵最低・上限、焼成、冷却、完成期限を入力して再計算する。

実装済み: 仕込み台1つを占有する順次仕込み、窯の時間別有限容量割当、期限・発酵上限の警告、4モード（自動＝2方式比較、完成期限順、発酵上限順、入力順）、工程タイムライン、天板+1枚のwhat-if、追加・編集・削除（最大30バッチ）、CSV工程出力、JSON保存/復元、localStorage自動保存/削除、印刷、モバイル表示。ネットワーク通信は実装していない。

自動計画は**最適化の保証はないヒューリスティック**。5分単位の時間、当日24:00までの焼成開始・終了、同一温度で利用可能な1つの窯を前提とする。窯の予熱・温度切替・天板の形状、工程間の成形・ベンチ、冷却棚容量、複数スタッフの動線、夜をまたぐ発酵、品質や食品安全は考慮しない。入力した発酵上限は品質判定ではなく、ユーザー指定の計画閾値。実作業は現場の判断・設備仕様と照合すること。CSVには数式注入回避処理あり。JSON importはサイズ制限・値検査あり。
