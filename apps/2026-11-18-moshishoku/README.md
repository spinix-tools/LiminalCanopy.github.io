# もし食卓 / MOSHI SHOKUTAKU

**備蓄があっても、断水・停電時に調理できるとは限らない。** 在庫を「食数」だけでなく、賞味期限・水戻しに使う水・1日あたりの加熱枠から献立に割り当てる、日本語・登録不要の静的Webアプリ。2026-11-18 制作。

## 対象と需要の根拠

一人暮らし・家族世帯の防災担当者、学校・地域の備蓄ワークショップ。内閣府の2025年8月調査（2025-12-24掲載）では、家庭で3日分以上備蓄しているものとして飲料水69.8%、食料品59.8%（複数回答）。未備蓄だけでなく、**所有済みの食品を具体的な食事に使えるか**という課題がある。政府広報（2026-02-13）は水1人1日3L、食品最低3日〜1週間、ローリングストックを紹介。農林水産省の食品ストックガイドも日常食品の活用と簡単レシピを掲載。

## 競合と差別化仮説

- 日本：[東京備蓄ナビ](https://www.bichiku.metro.tokyo.lg.jp/tool/) は質問から必要備蓄品・量を提案。
- 海外：[Stowd](https://stowd.app/) は期限順ローテーションと備蓄日数、[PPantry](https://ppantry.app/) は期限・在庫・備蓄可能日数、[PrepVault](https://prepvault.askmydata.pt/) は水・食料・期限・箱別管理を提供。既存機能を「新規」とは主張しない。
- **仮説**：日本語で「停電＋水不足」の時、準備方法と水・加熱枠を含む**朝昼夜の試算表**がすぐ見える小型ツールには、単純な在庫表とは異なる価値がある。ただし競合との独自性・実需要はユーザーテストで要確認。

## 実装した機能

- 人数1〜12名、1/3/5/7/14日、開始日、備蓄水量と最低確保量、調理水上限、加熱枠を変更
- 食品ごとの食数、主食/主菜/副菜、調理条件（そのまま/水戻し/加熱）、賞味期限の登録・修正・削除
- 期限の早い食品を優先し、1日3食へ食数を割当。準備水・加熱枠不足の食品を割当不可にし、不足食数・水不足・期限間近を表示
- 期限60日以内のローリングストック候補、購入リスト、献立CSV・購入CSV、JSONバックアップ・復元、印刷、ブラウザ内のlocalStorage保存
- 完全静的、外部CDN・API・追跡・課金・外部送信なし。食品名にHTMLを入力してもテキストとして表示。CSV関数開始文字をエスケープ

## 起動・検証

`index.html` をブラウザで開く。依存パッケージ不要。アルゴリズムは決定的な貪欲割当で**最適献立を保証しない**。

- `node --test engine.test.cjs`：**22 / 22合格**（日時、期限、在庫不足、水・加熱制約、CSV対策、決定性など）。
- `python browser_test.py`：**27 / 27合格**（追加/編集/削除、再計算、JSON取込、CSV/JSONダウンロード、XSS文字表示、375pxレイアウト）。Chromiumの管理環境では `file://` ナビゲーションが拒否されたため、テストでは**同一のHTML/CSS/JSをページに直接注入**。localStorage永続性、実配信、プリンタ実機は未検証。

## 限界と安全性

食数は「1人1食分」の**ユーザーによる概算**であり、栄養バランスやカロリーは計算しない。加熱枠は**実際の燃料量ではない**。水の不足は公的な1人1日3Lを基準とする参考値で、調理の可否は「入力した最低確保水量」と調理用水上限から試算。水の安全性、調理器具、衛生用水、調理後保存、個人の医療・アレルギー・乳幼児・介護上の要件は評価しない。賞味期限を過ぎた食品は計画から便宜的に除外するが、食品の安全性は判定しない。実災害の指針・必要量の代替に使わないこと。
