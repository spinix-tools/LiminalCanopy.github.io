# 釣足 / TSURITASU — 出店の釣銭試算

**作成日:** 2026-11-23 / **対象:** 学園祭・マルシェ・フリーマーケット・地域売店などの小規模現金販売。

## アイデア・調査

金種の準備枚数、商品価格と販売比重、現金払いの傾向を入力し、お釣りが不足する取引を事前にシミュレーションする、アカウント不要の日本円専用Webアプリ。

国内では、経済産業省の[2026-03-31公表資料](https://www.meti.go.jp/press/2025/03/20260331006/20260331006.html)によれば2025年キャッシュレス決済比率が**58.0%（国内指標）**。残り42%が現金決済件数であるという意味ではないが、現金運用を検討する余地はある。アプリ需要・有料支払意思額は未確認。

国内競合の[お釣り電卓](https://apps.apple.com/jp/app/id367338685)は会計時の計算、[レジととのえ](https://apps.apple.com/jp/app/id6835095224)は金種集計とレジ締め、海外の[Till Counter](https://www.tillcounter.app/)は金種カウント、[NamSys Cirreon](https://test.namsys.com/solutions/cash-forecasting/)は企業向け金種別予測。**差別化仮説:** 小規模出店者向けに「販売前の金種不足場面」と「追加で救済できる取引」を見せる。競合と重なる部分は多く、需要・独自性・収益性は未検証。

## 動作と制約

- 単一の`index.html` にCSS・JavaScriptを同梱。ブラウザで開いて操作できます。CDN・外部API不要
- 1〜20商品の編集、9金種の初期枚数、1〜200件の取引数、標準・高額札多め・ぴったり多めの3シナリオ
- 6種類の固定乱数による釣銭不足数、個別に+5枚で救済できる金種の候補、残枚数グラフ
- 有界DPによる金種在庫を守った釣銭計算、手動1会計確認、JSON読込/保存、CSV試算明細、ブラウザ内保存
- 架空の支払モードを使う**計画ツール**であり、表示率は将来の不足確率ではありません。実会計、途中両替、2,000円札は対象外。実物の確認が必要

## 検証

**ローカル完全版**（同テーマの別実装）では Node.jsユニット33項目、乱数を使った最適性照合500件、取引収支の保存則100件、ChromiumでUI操作24項目が合格。Chromiumは環境制約により同じローカルHTML/CSS/JSをインライン実行し、localStorageをメモリで模擬。外部HTTP要求とJavaScript例外はともに0件。

**このGitHubの単独HTML版は別実装**で、ブラウザ操作テストは未実施。GitHubへの保存後に再取得・静的確認のみ実施（動作保証ではありません）。
