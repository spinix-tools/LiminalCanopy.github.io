# キュー守 / CUE-MORI

**日本語でイベントの進行表を作り、担当者の重複を避けながら「このキューが延びたら終演は何分押す？」を比較する、登録不要のオフラインWebアプリ。**

## 対象・選定理由

企業セミナー、学園祭、地域イベント、小規模ライブの進行担当、特にExcelを使って複数の進行レーンを手作業で調整している人。日本イベント産業振興協会（JACE）は2026-06-16に「2025年イベント消費規模推計報告書」を発売し、国内市場を継続調査している。[NIKKEI MESSE](https://messe.nikkei.co.jp/en/topics/144728.html) は2025年3月の展示会来場者数を公開しており、複数の運営現場が実在することを示す。これらは対象市場の存在を示すだけで、本アプリ固有の需要・市場規模・販売見込みを裏付けない。

## 国内・海外の競合と差別化仮説（2026-11-18確認）

- 日本: [GIGDECK](https://gigdeck.app/) はDJ/VJのタイムテーブルとLIVEタイマーを統合。[eventio](https://www.eventio.pro/) は文化祭・セミナー・マルシェ等のイベント制作全般を管理。
- 海外: [Rundown Studio](https://rundownstudio.app/) はキュー時刻の自動再計算、リアルタイム共有、台本/プロンプター等を提供。[Runsheet](https://runsheet.show/) はLive同期、超過時の後続時刻再計算、印刷に対応。
- **差別化仮説**: 複数レーン（舞台/音響/映像/受付）と同一担当者の占有、キュー間依存を入力し、**任意の1件が0〜45分押した場合の波及範囲・終演超過・余裕を同一画面で比較**する。完全ローカルでチーム登録もネット接続も不要。通常の進行表機能には多数の競合があり、独占的な新規性は主張しない。

## 実装機能

- 開始時刻・終了期限・イベント名、キューごとのレーン・担当・分数・最早開始・先行キューの編集。追加/削除/並べ替え。
- 依存関係をトポロジカルに処理。同一レーンの前のキュー、明示依存、同一担当者の重複を考慮して時刻算出。
- 一つのキューの遅延（0〜45分）を追加して差分を再計算。変更されたキュー、終了期限の超過、レーン別のタイムラインを表示。
- 循環依存・欠落参照の警告。カンファレンス/学園祭/空の進行表プリセット。
- UTF-8（BOM付き）CSV出力、JSON保存・JSON復元、印刷、ブラウザのlocalStorageへの自動保存。
- ビルド・外部ライブラリ・API・クラウドアカウント・利用解析・有料サービス不要。入力データの外部送信なし。

## 使い方

`index.html` を開く。`style.css`、`engine.js`、`app.js` は同じフォルダに置く。最初からサンプルが入っており、すぐに操作可能。CSVは**遅延試算側**の予定を出力する。JSONは遅延操作を除いた進行表本体を保存する。

## 検証

- Node.js v22: `node --test engine.test.cjs` **33/33 PASS**。依存順、同時担当、波及、終演超過、CSVクォート、循環依存、入力境界、深夜跨ぎ等。
- Chromium + Playwright: `python browser_test.py` **23/23 PASS**。編集、追加削除、遅延操作、リセット、終了超過、JSON/CSVのダウンロード、JSON読込、プリセット切替、モバイルレイアウト、JS例外。
- この実行環境の管理制限により `file://` ナビゲーションが遮断されたため、ブラウザテストでは**同一HTML/CSS/JSをインライン化した描画**を使用。通常のファイル起動、HTTP配信、印刷実機、localStorageの永続性は未検証。

## 限界と安全上の注意

- 最適なスケジュールは探索せず、決定的な**貪欲割当**である。入力リスト順（および依存関係）によって余裕時間が変わる場合がある。
- 同一担当者のリソース容量は1名と仮定。人員数、移動時間、機材、並列運用可能性はモデル化していない。
- 時刻表示はイベント開始日からの単純な分計算で、夏時間・タイムゾーン・複数日のイベントを扱わない。最大120キュー、キュー最長240分。同期・複数端末共有は非対応。
- 循環依存がある場合は該当部分をスケジュールできない（警告表示）。入力順によるレーン内の先行関係も依存グラフに含まれる。
- 本番の事故防止や会場の安全管理を保証するものではない。
