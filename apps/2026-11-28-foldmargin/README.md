# FoldMargin — 中綴じ余白ラボ

2026-11-28 / MVP。ZINE・同人誌制作者、小規模印刷所、DTP担当向け。`index.html` をブラウザで開くだけ。外部依存・通信・登録なし。

## 選定理由・競合
- 日本：日経印刷の技術ガイドはクリープ補正が小口を保つ一方ノドを詰めることを説明。https://www.nik-prt.co.jp/tech/press/nakatoji/
- 国内競合：紙とインクは折丁別補正・変倍を計算。https://kamitoink.com/tools/saddle-creep/
- 海外：Adobe InDesign はクリープを段階配分する。https://helpx.adobe.com/jp/indesign/desktop/print/print-booklets/adjust-creep-settings-in-booklets.html
- Countfolk は均一本文紙＋表紙の余白・面付けを計算。https://countfolk.com/booklet-creep-calculator/
- Booklet Imposer はPDF面付けと補正をブラウザで実行。https://bookletimposer.com/booklet-creep-calculator/

差別化仮説：任意の混合紙厚とページ別の小口・ノド余白を同時に扱い、同一紙4ページの共通補正が可能かを判定。単純な最大クリープ計算ではなく、解決不能なページを特定する。日本語のZINE向け検索流入・印刷所の入稿前相談が普及経路の仮説。需要規模・支払意思・競合の全機能は未検証。印刷所5社・制作者10人への匿名の操作評価が次の検証候補（未実施）。

## 使い方・モデル
外側から紙厚を入力（1〜50枚、4〜200頁、表紙含む）。ページ別に重要要素までの余白を上書き可能。外側の紙厚の累積をせり出しの簡易推定とし、誤差は各紙で独立に上下限を設定して最悪側を計算。寄せ量sを0〜上限の設定刻みで全探索し、4ページ中の最大余白不足を最小化、同点は小さいs。左・右綴じの面付け順も表示。JSONの単位はµm。サンプルは32頁、不足16→2頁、最内紙の上限1.38mm、提案0.8mm、最大不足0.4mm。

制限：単一の中綴じ冊子、全ページ同サイズ、ページ単位の水平移動モデル。実製本、圧縮、折り半径、断裁誤差、塗り足し、見開き絵柄、PDF編集は未検証・非対応。印刷所の指定を優先し二重補正しない。提案は実寸の保証ではない。

## テスト結果
`node test.cjs`：固定10件、独立のページ別総当たり参照計算との500生成ケース照合、200頁境界が合格。Chromium（同一HTMLのインライン読み込み）：サンプル、絞り込み、JSONダウンロード内容、不正入力と旧結果無効化、復元、右綴じ、390px幅の横はみ出しなしを確認。JS例外・HTTP(S)要求0件。実印刷は未実施。

重複確認：直近の会話、mainと専用ブランチの比較で返った300ファイル（51アプリディレクトリ）、creep/booklet/面付け/中綴じのコミット検索（各0件）を確認。全既存ソースの網羅検査ではない。PrintFitは印刷倍率の許容差計算で、今回は中綴じの余白補正。
