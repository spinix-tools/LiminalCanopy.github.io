# 列さばき / RETSU SABAKI

**2026-11-21 / MVP v1** — 小規模イベントの待機列を「始まる前に」試算する、登録不要・外部通信不要のWebアプリです。

## 対象・選定理由

対象は学園祭、地域催事、展示会の体験ブース、小規模ワークショップの運営担当者。30分ごとの来場者予測と受付・体験窓口の人数が決まっていても、ピーク時間の行列が想像しにくいという課題を仮定しました。

日本では、ぴあ総研が**2026年6月17日**に発表した2025年ライブ・エンタテインメント市場調査で、**年間動員9,223万人・公演100,820回**を報告しています。これらは市場背景であり、個別の行列計画アプリの需要を直接示すデータではありません。

- [ぴあ総研（2026-06-17）](https://corporate.pia.jp/sp/news/detail_live_enta_market20260617.html)
- [大阪・関西万博公式データ（来場者対応・暑熱対策の記録）](https://www.expo2025.or.jp/expo_data/)

## 競合と差別化仮説

- 日本： [Airウェイト](https://airregi.jp/wait/ep/) は番号券、呼出、多言語対応など現場の順番待ち運用に強い。
- 海外： [Waitwhile](https://waitwhile.com/solutions/queue-management-system/) はバーチャル行列、通知、待機時間推定を提供。[Qminder](https://www.qminder.com/features/analytics/) は運営状況と待機時間分析を提供。
- 近接競合： [MySolvers](https://www.mysolvers.com/) はブラウザ上の離散事象シミュレーションを提供しており、「シミュレーションが唯一無二」という主張はしません。

**仮説**：既存サービスが現場での発券・呼出や汎用シミュレーションに強い一方、少人数催事に必要な「30分×6枠の混雑予測、現在配置と改善配置の共通乱数比較、待機場所の上限超過警告、1人増員する枠の候補探し」を単一画面・匿名・無料のローカルツールに絞ると使いやすい。市場適合性・有料転換可能性は未検証。

## 使い方と実装機能

ZIPを展開して `index.html` をブラウザで開きます。`engine.js`、`app.js`、`style.css` は同じ場所に置きます。

1. 来場予想・現行スタッフ・改善案スタッフを30分ごとに6枠入力。
2. 1人当たりの平均対応分数、変動率、来場人数の変動率、待機列の物理上限人数、試行回数を設定。
3. 「この条件で比較する」で **平均待ち、90パーセンタイル待ち、15分超率、待機列の上限超過試行率、閉場時未処理人数、閉場後の対応時間、スタッフ人時** を比較。
4. 「改善枠を探す」で**基準案の1枠に1名だけ増員**した6候補（上限8人）を簡易探索して改善案に反映。
5. CSV結果、JSON設定の書出し・読込み、ブラウザ印刷、端末内保存が利用可能。

**アルゴリズム**：単一FIFO列と複数窓口の離散事象シミュレーション。各30分枠の来場人数は入力値から±変動率で試行ごとに生成。枠内到着時刻はおおむね均等、個別対応時間は平均±変動率の一様乱数。2つのスタッフ案は同じ来場・対応サンプルを使用。窓口を減らしても対応中の案件は完了させ、180分以降は最後の枠の窓口数で滞留を処理する仮定。90パーセンタイルは生成された全来場者の待ち時間から計算。結果は予測の保証値ではありません。

## 検証（2026-11-21）

- `node --test engine.test.cjs`: **15/15合格**（決定論的事例、増員時の非悪化、150件のランダム条件一致検証、100件の生成時刻境界等）。
- `node --check engine.js` / `node --check app.js`: **構文チェック合格**。
- `python browser_test.py`: **Chromium操作テスト合格**。初期表示、入力変更と計算、改善案探索、CSV/JSONダウンロード、JSON読込み、初期化、画面レイアウト、モバイル幅の横はみ出し防止、JSエラーなしを確認。
- 制約：管理環境ではローカルHTTPが `ERR_BLOCKED_BY_ADMINISTRATOR` のため、**実際と同じHTML/CSS/JSをインライン展開**してChromiumテスト。端末保存はabout:blank由来の制限を回避するため**模擬ストレージ**で検査。通常ブラウザの直接起動、localStorage永続性、実イベントでの精度・安全性は未検証。

## 注意とプライバシー

- 個人の氏名・連絡先を収集しない。外部API、AI API、CDN、広告、課金なし。データは端末内のみ。設定JSONには入力した値のみが含まれます。
- 行列密度、事故対策、熱中症、出入口、避難動線、バリアフリー、人員の休憩・熟練差、参加者の離脱、複数ステージ・優先レーンはモデル外。会場の安全計画、法令遵守、現場実測の代わりには使用できません。
- 最適化は1名×1枠の局所探索に限り、全体最適を保証しません。
