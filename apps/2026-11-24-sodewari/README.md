# 袖割 / SODEWARI

ボードゲームの複数セットで、適合確認済みの同一スリーブの余りを共有し、買い足す販売袋の組合せを最適化するローカルWebアプリ。`index.html` をブラウザで開く（依存ライブラリ不要）。

## 対象・選定理由（2026-11-24 調査）
- ボードゲーム収集家、ゲーム会・カフェの備品担当者。国内では [ゲームマーケット2025秋](https://www.gamemarket.jp/gamemarket/2025a) が2025年11月22–23日に開催され、[専門メディア](https://tgiw.info/2025/11/gm2025a-report-venue.html) は公式発表に基づき3万人と報告。海外では [SPIEL Essen 主催者](https://spiel-essen.de/en/press) が2026年10月26日に23万人の来場を発表。これらは周辺市場の活動指標であり、スリーブ計画ツールの需要や支払意欲ではない。
- 国内競合 [スリーブイン](https://sleeve-in.com/) は適合・袋数検索。海外 [BoardFit Atlas](https://boardfitatlas.com/tools/sleeve-pack-planner/) は製品別購入計画、[SleevIt](https://play.google.com/store/apps/details?id=com.gate.ninth.sleevecollections) は在庫管理・買い物リストも提供。
- 差別化仮説：同一製品の複数入数・価格を混ぜて最安化し、既存在庫のセット別配分と単一入数だけで買う場合との差を表示。調査範囲での仮説で、独占機能とは断定しない。まず収集家5人程度に実データで使ってもらい、買い過ぎ削減と入力負担を検証する。海外版は通貨・言語切替を将来検討。
- 既存専用ブランチの apps ディレクトリ名一覧と会話履歴を確認。今回の用途は明示的には見当たらなかったが、全既存ソースの精査は未実施。

## 使用方法・計算
1. セット名、実物適合確認済みの製品コード、枚数、予備枚数を入力。異なる商品は別コードにする。
2. 手持ちと購入候補の袋名・入数・円価格を入力（各欄60行、必要枚数は製品ごと1万枚まで、カンマは区切り専用）。
3. 計算。手持ちは上のセットから充当し、不足分は動的計画法で総価格、購入枚数、袋数の辞書式順に最小化。非負価格・袋在庫無制限のモデルで、不足数+最大入数-1まで探索すれば十分（これ以上では袋を1つ除いても不足せず改善できる）。販売袋が無い不足は未解決と表示。
4. CSV購入表、印刷、任意の端末保存。編集後は再計算が必要。サンプル価格は架空。送料、数量割引、店舗在庫、物理的適合、外貨換算は対象外。入力を外部送信しない。

## テスト
- `node test.cjs`: 15単体チェック、独立全探索との比較1000件合格（価格、枚数、袋数、復元内訳）。
- `python browser_test.py`: Chromiumで初期計算、編集、CSVダウンロード、保存・復元（localStorage模擬）、未解決、入力検証、リセット、390px幅、外部HTTP要求なし・JS例外なしを確認。管理環境の file:// 遷移制限のため同じHTMLをインライン実行。実機の永続化・現物適合・実際の購入は未検証。
- 外部APIや有料サービスなし。秘密・個人情報を要求する欄なし。
