# ひづけ仕分け / HIZUKE SHIWAKE 📷

**2026-11-20 / Hourly App Lab** — 日付の確からしさを混同せず、写真の整理済みコピーを日付別ZIPで作る、オフラインWeb MVP。

## 対象・選定理由（日本・海外の需要）

対象は家族写真・昔のデジカメ写真・紙写真スキャンを整理する個人、小さな地域資料室や家庭内アーカイブ担当者。アスカネットの2025年5月30日発表調査（日本の20歳〜60歳以上の597人）では、家族写真を「整理できていない」66.8%、「整理の途中」10.6%、合計77.4%。直接的な作業課題の指標だが、本アプリの利用意向や課金意向を示すものではない。

海外には本格的な管理・リネーム需要と競合があり、**digiKam**（オープンソース、EXIF日付や高度な一括リネーム）や **FolioSort**（Windows/Mac、EXIF補正・ファイル名からの補完・重複検査・ローカル処理）が既に提供されている。国内でも **おもいでばこ**（バッファロー）が写真分類機能を拡張している。日付抽出・ローカル整理・重複確認は新規技術ではない。

### 差別化仮説

**「EXIF撮影日（比較的強い根拠）」「ファイル名の日付（未承認の候補）」「不明」を画面とCSVで明示し、推測日付を本人が承認するまで確定しない。** EXIFとファイル名の読み込み→確認→保留写真の分離→元バイト列を保った日付別ZIP作成という限定ワークフローを、インストールもアカウントもなく利用できる。既存製品とのUX比較や顧客獲得、商業性は未検証。

## 動く機能

- JPG/JPEG・PNG・WebPのローカル追加（80枚、各20MB、合計200MBの制限）、ドラッグ＆ドロップ、オフライン生成したデモ写真4枚。
- JPEG EXIF APP1/TIFFの `DateTimeOriginal` を優先、無い時だけ `DateTimeDigitized` を読む（両者を別表示）。PNG/WebPのEXIF・XMPなどは対象外。
- ファイル名の `YYYYMMDD` / `YYYY-MM-DD` などから日付候補を抽出するが**採用までは日付未確定**。手入力で修正・保留への差戻し。
- 選択写真プレビュー、日付確定/要確認/完全一致重複フィルター、確定写真の月別棒グラフ。
- 写真を**バイト単位で比較**して完全一致重複を検出し、ユーザーが指定すればZIPから除外（原本は削除しない）。ファイル名だけ一致・サイズだけ一致は重複とは見なさない。
- 元の画像データを変更せずZIP（無圧縮）に日付別 `YYYY/MM/`、未確定は `unverified/` に配置。元ファイル名を残したリネーム、CSV/JSONマニフェストをZIPに同梱。CSV/JSON単体でも出力。CSVは式として解釈され得る入力の先頭を保護。
- `localStorage` に保存するのはプレフィックス・重複除外設定**だけ**。写真や選択中の原稿・日付修正は保持しない。バックエンド、外部JavaScript、ネットワーク送信、API、会員登録、課金はない。

## 使い方

同じフォルダーの `index.html` をブラウザで開く。写真をドロップするか **「動作を試す」** を押す。日付候補は採用するか手入力。日付不明は空欄のまま **日付別ZIP** を押す。オリジナルには書き込まず、ZIPの別コピーだけを生成する。ファイルの内容・EXIFを含むZIPを他者に渡す場合、**GPSなど元画像のメタデータもそのまま残る**ため公開前に別途確認すること。

## 既知の範囲・注意

- ZIPはブラウザメモリに組み立てるため、上限内でも端末によって処理不能な場合がある。ファイル内容は無圧縮、圧縮率ゼロ。JPEG APP1の最初の256KBを解析し、特殊な大容量メタデータや破損ファイルでは日時が見つからないことがある。
- EXIF `DateTimeOriginal` もカメラ時計誤設定の可能性があり、証明された撮影事実ではない。`DateTimeDigitized` はスキャン日などで撮影日とは限らない。ファイル名推測は利用者が採用して初めて仕分けに使う。タイムゾーンは補正しない。
- 画素の類似・同一写真の再圧縮版は検出しない。ZIP画像のメタデータ、GPS、顔は変更・削除しない。ブラウザに読み込んだ画像・日付修正はリロードで消える。
- 画像サイズやZIP名に異常な文字がある場合は簡易サニタイズを実施。企業用の大量データ管理・法的証拠保全やデジタルフォレンジックを目的とした製品ではない。
