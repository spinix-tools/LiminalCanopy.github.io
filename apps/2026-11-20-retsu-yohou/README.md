# 列予報 / RETSU YOHŌ

イベントの受付行列を**15分刻みの来場人数 × 受付スタッフ人数 × 受付所要時間**から予測し、現状Aと比較案Bを並べる、登録不要・オフラインの日本語Webアプリ。

## ターゲットと選定理由

地域祭り、同人イベント、学校行事、300〜1,000人規模の小規模催事を運営する主催者・ボランティア責任者。**入口のピークだけ配置を増やしたいが、事前の定量的な判断手段が少ない**という仮説を検証するMVP。

市場の周辺指標：ぴあ総研の**2026-06-17**公表によると2025年の日本国内ライブ・エンタテインメント動員は**9,223万人**・公演**100,820回**（https://corporate.pia.jp/sp/news/detail_live_enta_market20260617.html ）。海外ではLive Nationの**2026-11-05**発表で、2026年10月までの販売チケットは**1億7,000万枚**（https://news.livenationentertainment.com/news/live-nation-entertainment-reports-third-quarter-2026-results ）。どちらも**小規模イベントでの本アプリの直接需要を証明しない**。

競合：国内の**Airウェイト**は番号券、待ち組数・待ち時間管理と有料分析レポートに対応（https://airregi.jp/wait/ep/ 、https://faq.airwait.jp/hc/ja/articles/207699527-分析レポートを活用する ）。海外の**Waitwhile**は受付・予約・リアルタイム待ち列の運用、分析を提供（https://waitwhile.com/ ）。

**差別化仮説**：実際の顧客呼出や予約機能を作らず、導入前の「何時に何人を置くか」という仮説検証だけに特化。シフトごとのA/B比較、先着順シミュレーション、目標P95待ち時間を目指した追加スタッフ案、未処理人数の警告を、アカウント不要・外部送信なしで一画面にまとめる。収益性・利用意思は未検証。

## 使い方

`index.html` をモダンブラウザで開く（または静的Webホスティングに配置）。**ビルド・外部API・通信は不要**。12枠×15分の来場見込みとA/B受付人数、1人当たり受付時間を編集し、画面下の待ち人数グラフ・P95・未処理・延べ配置時間を比較。`A → B をコピー` 後 `Bに増員案を作成` で貪欲法による案を作り、JSON・CSVで保存／共有できる。端末内の `localStorage` に計画のみ自動保存。JSONから復元、印刷も対応。

## 計算と制限

- 固定seedの到着分布：各15分枠内に一様ランダム、処理時間は指定平均の0.7〜1.3倍を1分単位に切り上げ、先着順に処理。A/Bは**同じ来場者到着と処理時間**で比較。
- 配置人数の上限は**1枠あたり0〜12人**、予測人数は0〜500人、最大20枠。設定した最終枠のスタッフ数を終了後にも最大180分維持する仮定。シフト外の残業人時は**配置延べ時間の合計には含まれない**。
- P95は**完了者の待ち時間のみ**から算出。未処理者は必ず別表示し、過小評価に注意を表示。提案は1枠ずつ配置を増やす**近似の貪欲法**で、最小人数・最適解・目標到達を保証しない。到着データなし、受付窓口以外の導線なし。実際の安全・警備・消防計画や法令適合性の判断には使用しない。
- サンプル（334人）は計算上、現状AのP95 **135分**、比較B **27分**、どちらも未処理0人。ただしAの受付終了後処理が**137分**あり、Bも**28分**ある。
