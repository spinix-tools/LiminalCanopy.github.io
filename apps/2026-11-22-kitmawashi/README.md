# キットまわし / KITMAWASHI

小規模な学校・地域団体・図書館・メイカースペース向けの、**共用部品を使う貸出キットの予約衝突チェッカー**。2026-11-22制作。ブラウザのみで動く日本語MVP（オープンソース・MIT）。

## ターゲット・選定理由

小さなAV機材室、サークル、工具ライブラリーの担当者。「インタビューセット」と「配信セット」が同じマイクやバッテリーを使うため、キット名だけの予約台帳では欠品に気づきにくい。国内ではデジタル庁が2026年4月1日付のシェアリングエコノミー推進ページで遊休資産活用を位置づけている。AsMamaの2022年6月22日公表（1,002人対象）調査では78%が近隣の私物貸借アプリに興味を示した。ただし小規模キット予約アプリの購入需要を証明するデータではない。

- デジタル庁（最終更新 2026-04-01） https://www.digital.go.jp/policies/sharing_economy
- AsMama（2022-06-22） https://asmama.jp/locapi_needs/

## 競合と差別化仮説

- **国内**：カシカンは備品登録、在庫・予約・返却に対応（ https://apps.apple.com/jp/app/id1553246735 ）。KashiTeはQR貸出を利用者の会員登録なしで提供（ https://kashi-te.com/about ）。
- **海外**：myTurnは物品予約・貸出、リマインダーを提供（ https://myturn.com/lending-libraries/ ）。Booqableは2026年8月19日時点のヘルプで数量付きバンドルと在庫連動を説明（ https://help.booqable.com/en/articles/3797998-how-to-create-product-bundles ）。Cheqroomもキット・バルク在庫に対応しており、キット管理自体は新規性ではない（ https://knowledge.cheqroom.com/helpcenter/kits-overview ）。
- **仮説**：高機能な運用管理と競争せず、**キット間の共有部品衝突／確定予約対候補の独立評価／21日以内の代替日**を登録・外部送信なしで数分で検査する「事前確認特化」に絞る。受容性、支払意思、実運用での精度は未検証。

## MVPの操作

1. `index.html` を同じフォルダにある `style.css`、`engine.js`、`app.js` とともに開く。あるいは **`standalone.html` を単独で開く**（本体をすべて内包）。
2. 「部品の在庫」で種類と数量を編集し、「貸出キットの構成」で1セットあたりに必要な部品数を指定する。
3. 貸出名・キット・期間・数を入れて候補追加。確定予約との衝突を判定し、可能なら確定、不足したら候補を代替日へ移動する。
4. 色別の8日間ヒートマップで確定のみ／候補込みの負荷を比較。JSON・CSV出力、JSON読込、Undo、端末保存、デモ初期化が可能。

計算法：開始〜返却予定日を**両端含む日単位**で占有。各日の部品使用数＝当日有効な予約の「キット当たり必要数×キット数」の合計。確定可否は、**その候補1件＋既存確定予約**だけで判定。候補同士を含む全計画の衝突も別表示する（すべての候補を確定できる保証ではない）。代替日は元開始日の翌日〜21日後を順次探索し、期間長は保つ。

## 検証結果（2026-11-22）

- `node --test engine.test.cjs`：**21/21合格**。不正日付・参照整合性・共有部品の需給、**500件ランダム需要突合**＋**250件代替日不変条件**を含む。
- `python browser_test.py`：**38/38合格**。システムChromiumで編集・予約候補の移動／確定・JSON/CSV・Undo・モバイル幅などを操作、例外と外部HTTP要求0件。
- 管理環境では `file://` / `data:` ナビゲーションがブロックされたため、操作テストは同一ソースをインライン化した `standalone.html` を `page.set_content()` で実行した。`localStorage` はテストで模擬し、ページの再描画に対する保持を確認。通常のローカルファイル起動・長期保存・実現場での運用は未検証。

## 設計上の制限・プライバシー

1日単位であり、返却直後の再貸出、整備バッファ、故障・個体識別、複数拠点、移動、権限管理、同時編集は扱わない。各キットの構成部品は種類別在庫のプールとして算出する。意図的なオーバーブッキングは確定ボタンで防止するが、在庫数変更後の既存確定予約には警告のみを表示する。予約ラベルには個人名を入れないこと。端末の共有や履歴へのアクセスにも注意。外部API・有料サービス・追加課金・通信・利用者情報収集は不要。
