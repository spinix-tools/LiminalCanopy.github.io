# KeyPrism — キー正規化監査 v1.0

対象：EC商品マスター、在庫管理、ETL・データ移行担当者。個人情報ではなく商品コードなどの非個人キーを対象とする。

選定理由（2026-11-28調査）：国内の [Name-Catch](https://any.co.jp/product/name-catch/) は表記統一による重複候補抽出を提供。海外の [CSV Lookup Key Audit](https://tools.devbrickstech.com/tools/csv-lookup-key-audit) は完全一致の結合前監査、[Fuzzy CSV Join](https://gizza.ai/tools/fuzzy-csv-join/) は類似度による結合を提供。需要の存在を示す間接証拠であり、市場規模・支払意思は未確認。

差別化仮説：完全一致と選択した正規化後を同時比較し、増加ペア、消失ペア、新規の複数候補左行、同一側の異なる原値の衝突を明示する。結合や自動削除を行わず、候補の根拠を原値・件数で残す。競合に同等機能がないとは断定しない。

使い方：index.html をブラウザで開き、左右のキー列を見出しなし・1行1件で貼り付ける。ルールを選び比較監査。JSONで全グループを保存できる。空文字は照合対象外。空白だけの原値は完全一致時には非空扱い。末尾改行1個は終端として扱う。NFKC、小文字化、前後空白、ハイフン、先頭0の変換は別コードを統合しうる。複数候補とは右側の行が2件以上あること。衝突とは同一側の異なる原値が同じ非空キーに写ること。実際の結合は行わない。各20,000行・200万文字まで。ネットワーク・永続保存・外部依存なし。

検証：`node test.cjs` で固定10件、独立ペア全列挙500件、左右各20,000件（4億ペアを生成せず計数）が合格。`python browser_test.py` でChromiumの操作、JSON保存、無効入力、HTML文字列の非実行、390px幅、HTTP通信・JS例外0件を確認。環境のfile://制限により同一HTMLのインライン読み込みで検証。初期例は一致ペア4→6、複数候補の左行0→1、衝突1。先頭0除去で7ペアになるが正しい対応とは限らない。DB固有の照合順序、Excelの型変換、複合キー、実データ・収益性は未検証。

重複調査：会話内の直近作品、mainと専用ブランチの比較結果300ファイル（51アプリディレクトリ）、normalization / join / 名寄せ / collision のコミット検索（各0件）を確認。全履歴・全ソースの網羅確認ではない。
