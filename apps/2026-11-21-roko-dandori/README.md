# 露光段取り / ROKO DANDORI 📷

**フィルム長時間露光の「1枚あたりの補正計算」から「撮影全体の時間割」へ。** 完全ローカルの静的HTML/CSS/JavaScript MVP（2026-11-21）。`index.html` を開く。ビルド・ログイン・API・課金・通信は不要。Node.js 22+ で `node --test engine.test.cjs`。

## 誰に・なぜ

**対象:** フィルム写真愛好者、暗室・写真講座の講師、海辺や夜景でNDフィルター／ブラケットを使う人。複数カットの撮影順と最終終了時刻を先に確認する、紙の撮影票が目的。

**日本市場の手掛かり:** デジカメ Watch の2026-08-25記事が紹介した「フィルム写真に関する実態調査2025」は、2025年11〜12月の自己選択式調査で**1,337回答**を収集。写真フィルムの継続利用者がいることは分かるが、代表標本ではなく、本アプリの市場規模・課金需要を意味しない。[デジカメ Watch](https://dc.watch.impress.co.jp/docs/news/2135076.html)。ITmedia（2025-09-22）は「写ルンです」の再人気と2025年アプリ投入を報道。[ITmedia](https://www.itmedia.co.jp/business/articles/2509/22/news030.html)

**競合（調査日2026-11-21）:** 国内 [NDLab](https://photo-ai-studio.com/ndlab) は ND/CPL露光計算、iPhone用 [ND露出計算ツール](https://apps.apple.com/jp/app/id6784561741) はND重ね付け・露光タイマー・設定保存に対応。海外 [Actinic](https://obelisk.club/actinic) はフィルム別相反則不軌補正、[TimerGlass](https://apps.apple.com/us/app/timerglass/id6761681913) は実フィルム曲線・ND合成・タイマー、[Dorkroom](https://dorkroom.art/docs/dorkroom-tools/reciprocity-calculator) は補正計算を提供。**ND補正、相反則補正、タイマー、オフラインという個別機能に新規性はない。**

**差別化仮説:** 複数シーンと±1 EVブラケットをまとめて「露光・コマ間準備・予定終了時刻・時間超過」を一度に計算し、**現場用コマ順撮影票とCSVを出す**用途に絞る。すでに強い競合があり、導線短縮が勝つか、顧客需要・利用継続・収益性は未検証。

## 実装済み

1. 複数シーン（最大16件）、測光時間（`1/125`または秒数）、NDフィルター2枚、補正指数p（1.00〜1.80）、±1 EVブラケットの編集・追加・移動・複製・削除。
2. 露光計算: `t_filtered = t_meter × ND1 × ND2 × 2^EV`。`t_filtered > 1秒` の場合に限り、例示的なモデル `t_corrected = t_filtered^p`。1秒以下はそのまま。最大48コマ。**実フィルム固有の補正は内蔵しない**。
3. 準備インターバル、開始時刻、総撮影枠からタイムラインと超過警告、コマ別開始／終了時刻（翌日への繰越含む）を表示。
4. 操作中の露光時間を使う手動タイマー（開始／一時停止／リセット）。`Date.now`基準でブラウザの間欠処理時の遅れを軽減するが、シャッター開閉・通知・バックグラウンド動作を保証しない。
5. CSV撮影票・JSON書出／復元・ブラウザ内への明示保存／復元・印刷。ユーザー入力は画面でtextContent等により表示し、CSVの表計算式注入を軽減する。

## 使用上の限界

フィルムごとの指数は公開データを参照して**利用者が自分で指定**する。`t^p` は単純な例示モデルで、メーカーの区分的な補正式・露光や色ずれの補償とは異なる場合がある。NDフィルターの公称倍率と実透過率、光量の時間変化、現像条件、手動操作遅延は計算に入らない。本MVPは測光器・撮影機材の代替ではない。標準的ND倍率については[ケンコー・トキナーの解説](https://www.kenko-tokina.co.jp/special/brand/kenko/nd_speed.html)を参考にした。サンプルは架空設定。

## 検証

`node --test engine.test.cjs` で入力検証、NDの乗算・補正閾値、ブラケット、時間保存則、日跨ぎ、CSVインジェクション軽減、JSON、乱数500ケースの不変条件を確認。`python browser_test.py` で実際のブラウザの画面操作、ダウンロード、入出力、画面幅を確認（テスト実行環境にPlaywright/Chromiumがある場合）。**実施結果（2026-11-21）:** Node.js単体テスト **37/37合格**、固定シード乱数 **500件合格**、Chromium UI操作 **37/37項目合格**、デスクトップ・モバイル表示確認、テスト中のJS例外および外部HTTPリクエスト **0件**。環境制約でChromiumは `http://127.0.0.1` ナビゲーションを `ERR_BLOCKED_BY_ADMINISTRATOR` として拒否したため、同一HTML/CSS/JSをブラウザへ直接展開して試験し、localStorageは模擬した。**通常URL・file://からの直接起動と保存永続性、実機フィルム露光、撮影現場、課金需要は未検証。**

## プライバシー・ライセンス

外部スクリプト・外部送信・APIキー・アカウント・分析SDKなし。入力は撮影場面の任意メモのみで、個人情報を求めない。端末保存・JSON/CSV保存はユーザーがボタンを押した場合にのみ行う。MIT License。
