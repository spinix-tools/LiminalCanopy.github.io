# 巡り皿 / MEGURI ZARA

地域イベントで使う**リユース食器の清潔在庫・未洗浄回収・貸出中**を混同せず、事前の必要在庫と当日の数量実績を管理する無料・ローカル完結型Webアプリです。

## 対象と選定理由

対象：地域マルシェ、学園祭、自治体催事、NPO、リユース食器導入担当者。

- **日本の需要の手掛かり**：東京都北区は2026年2月19日に、2025年10月の地域イベントで飲食店5店舗が協力したリユースカップ実証実験を報告。[北区公式](https://www.kankyoportal.city.kita.lg.jp/news/2804)
- 港区は2026年5月1日更新の案内でイベント向けリユース食器のレンタル補助を紹介。[港区公式](https://www.city.minato.tokyo.jp/gomigenryou/riyu-susyokkihojyo.html)
- 大阪市は2026年11月4日にイベント主催者向けリユース食器導入ガイドを公開し、**回収食器を各店で洗って再使用しない**よう注意している。[大阪市公式](https://www.city.osaka.lg.jp/kankyo/page/0000687593.html)
- **海外の市場・競合**：ドイツの[RECUP](https://recup.de/)は預り金と回収・洗浄に基づく再利用ネットワークを運営。[ドイツ環境支援団体DUH](https://www.duh.de/presse/pressemitteilungen/pressemitteilung/erfolgreicher-mehrweg-pilot-von-deutscher-umwelthilfe-und-berliner-umweltverwaltung-leergutautomate/)は2026年6月29日に2025–26年の共通返却インフラ実証を報告。これらは広域の運用サービスであり、本アプリと提供範囲が異なる。

これらは採用・制度面の需要の*兆候*であり、本ツールの顧客数・市場規模・収益性を示すデータではありません。

## 差別化仮説

大規模な容器追跡・決済サービスではなく、**イベント前日に5分で試算して、当日も個人データ・容器IDなしで数量精算できる**道具に絞る。特に「返却済みだが未洗浄」と「再配布可能」を明確に分離し、返却率が高くても清潔在庫の不足が解消しないことを示す点に価値があると仮説を置く。競合の全機能比較、ユーザーインタビュー、価格受容性は未実施。

## MVP機能

- 1～24時間枠の需要・清潔食器補充予定を直接編集し、清潔在庫・貸出中・未洗浄返却・不足を計算
- 想定回収率・返却タイムラグ・預り金（1個当たり）を設定
- **最大累積不足に基づく必要初期清潔在庫**を算出し、ワンクリック採用
- 需要と提供可能数の時刻別グラフ、時刻別テーブル、イベント終了時の貸出中と預り金（理論値）
- 当日記録：提供／返却（未洗浄）／洗浄済み品の到着／清潔在庫から除外、数量不足時は記録を拒否
- 取引履歴・Undo、数量保存式の照合、JSON保存・読込、CSV出力、印刷、端末内保存
- 完全静的ファイル。登録・Cookie・外部API・追加課金・個人データ送信なし。保存はブラウザのlocalStorage。

## 計算の前提・限界

各枠の**開始時**に清潔な補充品が到着し、その後需要を満たす。返却は前に提供できた数量×回収率の切り捨て分が指定枠後に戻る。イベント内で返却品を清潔在庫へ自動加算しない。必要初期在庫 = `max(0, 各時点の累積需要 − 累積清潔補充 の最大値)`。混雑、破損、衛生、予約、輸送遅延の余裕は含まない。返却までの時間は離散モデルであり実測予測ではない。返却がイベント後に発生する分は終了時点の貸出中と区別して補助表示。

当日台帳の「預り金残」は `貸出中数×設定単価` の理論値であり、実際の現金や支払方法の照合ではない。**現場での洗浄や再使用を推奨するものではない**。食器の衛生管理は保健所・主催者・専門事業者の指導に従う。

## 実行

1. `index.html` と `engine.js` を同じフォルダに置き、モダンブラウザで `index.html` を開く（または任意の静的Webサーバーで配信）。
2. 事前計画で時間帯・需要・外部から届く洗浄済み補充を入力。推奨在庫を採用するか手動で調整。
3. 当日記録で取引を入力。必要に応じてJSON/CSVをローカル保存。

## 検証（2026-11-22）

- `node --test engine.test.cjs`：**24/24件合格**。600件の決定論的ランダム計画で数量保存・最小初期在庫を、400系列×30操作の台帳で数量保存を確認。
- `python browser_test.py`：**34/34件合格**（Chromium）。画面操作、条件変更、JSON/CSVダウンロード、返却制限、実績のUndo、モバイル幅、模擬localStorage、外部通信・JS例外なしを確認。
- ブラウザの管理制約で127.0.0.1がブロックされたため、**同じindex.htmlとengine.jsの内容をインライン結合**し、`localStorage`のみインメモリ実装へ差し替えて検証。直接 `file://` 起動・実ブラウザ保存永続性・外部ディスプレイ印刷精度は未検証。
- 実イベントのデータを用いた精度検証・衛生管理評価は未実施。最適性は上記単純な補充時点ルールの範囲に限定。
