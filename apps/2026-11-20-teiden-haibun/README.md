# 停電配分室 / TEIDEN HAIBUN

停電時に「このポータブル電源で家電を何時間使えるか」を、**家電ごとの時間帯・必須/任意の優先度・予備残量**を使って比較する、登録不要・オフラインのWebアプリMVP。

## 対象と選定理由（2026-11-20 時点の調査）

- **日本**：災害時の携帯発電機・ポータブル電源の取扱いについて、NITEは2025-08-28に製品事故への注意喚起を公表。停電対策は現実的な生活課題（ただし当アプリの有料需要を直接示す統計ではない）。[NITE](https://www.nite.go.jp/jiko/chuikanki/press/2025fy/prs250828.html)
- **海外**：米EIAは2025-12-01に、2024年の全米の平均停電時間が11時間だったと発表。災害時の備えに関連需要がある。[EIA発表の転載](https://ebs.publicnow.com/view/1B29E57BEE5C28D6A94CD77A986C7360C3E72FF3) ／ [米CDCの停電備え](https://www.cdc.gov/prepare-your-health/take-action/power-sources.html)
- **競合**：日本の[Jackery使用時間計算ガイド](https://www.jackery.jp/blogs/power-station/using-time-of-power-station)や[Jackery製品ページの時間シミュレーター](https://www.jackery.jp/products/solar-generator-500-new-100w)、海外の[BackupCalc](https://backupcalc.com/power-station-runtime-calculator/)・[StationVerdict](https://stationverdict.com/runtime-calculator/)が実際に稼働時間と最大出力の計算を提供する。単なる「Wh÷W」は既存機能である。
- **差別化仮説**：「1台の連続稼働時間」ではなく、**毎日の使用時間割と必須/任意の優先順位を組み込み、予備電力を残すA/B計画と未供給時間を一画面に示す**ことで、防災の事前計画がしやすくなる。競合機能を網羅的に検証した主張ではなく、利用者検証が必要な仮説。

## 実装済み

- 24・48・72時間の1時間刻み試算／翌日への同じ時間割の反復、深夜をまたぐ時間割。
- 家電の名称、W、台数、平均稼働率、開始・終了時刻、必須/任意の編集・追加・削除（最大36件）。
- 電池容量Wh、初期残量、予備率、変換効率、連続定格出力の編集。
- **通常案A**と、必須家電を優先して**任意家電の平均使用率を一律削減する省エネ案B**を自動生成。必須だけでも不足する場合、解決済みと表示しない。
- 時間ごとの電池残量SVGグラフ、定格出力超過時間・未供給Wh・初回の給電不足・時刻別内訳。
- ブラウザ内保存（localStorage）、JSON入出力、CSV出力、印刷、スマートフォン対応。
- バックエンド・外部API・アカウント・個人情報収集・有料サービス・CDNは不要。

## アルゴリズムと限界

各時間の推定平均W = `Σ(定格W × 台数 × 平均稼働率)`。蓄電池からの消費Wh = `推定平均W ÷ 変換効率`。初期Wh = `容量 × 初期残量%`。予備Wh = `容量 × 予備率%`。計画で利用可能なWhは `max(0, 初期Wh − 予備Wh)` とし、超過した分は未供給と計上する。B案では必須需要を優先し、残余エネルギーに収まるよう任意家電の平均稼働率に同じ倍率を適用する（0.1%刻み）。必須だけで足りない場合は任意家電をゼロにして不足を警告。保守的な出力警告として、同時使用時間帯の**各機器の定格W合計**と電源の連続出力を比較し、A案が超過する場合のB案では任意家電を全停止する。定格出力の超過は「危険な可能性がある警告」であり、シミュレーターはそれでもエネルギー需要を参考計算する（実際に運転できるという意味ではない）。

**安全上の限界**：起動時突入電流、機器ごとのスイッチング、DC/ACポート差、放電特性、温度、経年劣化、発電/太陽光、ケーブル定格、接続相性を反映しない。医療機器や生命維持、接続可否や安全性の判断に使えない。メーカー資料と公的な防災情報を確認する。[国民生活センター 2025-08-28](https://www.kokusen.go.jp/mimamori/mj_mailmag/mj-shinsen519.html)。実機検証・利用者評価・収益性検証は未実施。

## 起動・テスト

`index.html` を通常のブラウザで開く。外部資産なし。開けないブラウザでは `python -m http.server 8000` をこのフォルダで実行して `http://localhost:8000/` にアクセス。

```bash
node --test engine.test.cjs
python browser_test.py  # Python Playwright と Chromium が使える環境
```

**この実行での結果**：Node.js v22 の単体 **31/31件成功**、固定シードを使ったランダム制約 **500件成功**、構文チェック成功。ChromiumでUI操作 **28/28件成功**（追加編集削除、72時間・日切替、JSON/CSV、JSON復元、モバイル幅確認、端末保存を模した再読み込み）。ただし管理環境の `file://` 遷移が `ERR_BLOCKED_BY_ADMINISTRATOR` となったため、ブラウザ検証は**同じ4つのHTML/CSS/JSの内容をHTMLにインライン展開した検査版**を使用、`localStorage` はテスト用スタブを使用。通常の `file://` 直接起動・実ブラウザの保存永続性は未検証。

サンプル（1024Wh/初期95%/予備20%/効率85%/24h）では通常案の未供給約1172.2Whに対し、省エネ案で任意家電の平均利用率を14.1%にすると計算上は未供給0Wh。ただし実際の機器動作・安全性・災害時の給電を保証しない。
