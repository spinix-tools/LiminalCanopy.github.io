# まにあう帖 — 期限より前に、動く日を。

**2026-11-16制作 / 単体HTML / 無料 / 外部APIなし**

無料トライアル、サブスク解約、EC返品、製品保証などの「最終期限」と、その前に着手する「行動日」を分ける日本語Webアプリです。`index.html`を開くだけで動き、データはブラウザの `localStorage` に保存します。外部ライブラリ、アカウント、アクセス解析は使いません。

## 想定ユーザーと課題

日本の個人消費者。契約更新の前に解約したい、返品の発送に数日必要、保証の問い合わせに証拠を探す時間がいる、という人。締切日を一つだけ記録しても実際の手続きに間に合わないという課題を対象にします。需要規模と利用継続率は未検証です。

## 選定根拠と競合確認（2026-11-16時点）

- **国内需要の根拠:** 船橋市消費生活センターは2026年9月25日、無料体験から有料へ移行した事例と、アプリ削除だけでは解約にならない問題を掲載。<https://www.city.funabashi.lg.jp/shisetsu/shiminkatsudo/0001/0002/0002/p150206.html>
- **契約確認の重要性:** 政府広報オンラインは2025年9月22日に、定期購入と無料トライアルの契約条件を確認する必要を説明。<https://www.gov-online.go.jp/article/202012/entry-9175.html>
- **日本の競合:** 「サブベル」は契約更新日と解約締切を別々に管理し、端末内保存も提供。期限管理やプライバシー自体は新規性ではない。<https://apps.apple.com/jp/app/id6812237264>
- **海外の競合:** Rocket Moneyは継続支払いの一覧化や解約代行を提供し、解約代行の一部機能は有料会員向け。<https://www.rocketmoney.com/feature/manage-subscriptions> / <https://help.rocketmoney.com/en/articles/934402-how-do-i-cancel-a-subscription-on-rocket-money>
- **隣接競合:** Warranty Tracker & Receipts は返品期限と保証期限を端末内で管理。<https://apps.apple.com/cy/app/warranty-tracker-receipts/id6779882216>

**差別化仮説:** サブスク「だけ」・購入品「だけ」ではなく、**契約を離れる／権利を行使するための行動を横断して1画面に集約**し、契約上の最終期限と、自分で必要とする準備日数を明確に区別する。ブラウザで使え、データ持ち出し（JSON）と任意のカレンダー連携（ICS）で通知や特定事業者への依存を抑える。既存アプリと重複する機能が多く、優位性は仮説段階です。初期検証では「登録継続率」と「カレンダー書き出し率」を測る必要があります。

## 実装済み

- 期限の登録・編集・削除、カテゴリ選択、任意の金額・公式URL・手続きメモ
- 準備日数を最終期限から減算して「行動日」を表示（閏年・月跨ぎ対応）
- 要対応／7日以内／期限経過／完了での絞り込み、検索、行動日での並び替え
- 手続き結果を自分で確認した後に完了状態へ変更（*完了が法的効果を保証するわけではない*）
- デモデータ、要点コピー、JSONバックアップ／復元（上書き確認付き）、未完了分の `.ics` カレンダー書き出し
- 端末内データ保存（利用できない場合は警告）、単体HTML、モバイルレイアウト、入力文字のHTMLエスケープ、HTTPSリンク限定

**重要な制約:** 約款や契約条件から期限を自動取得せず、ユーザーが確認した期限を入力します。通信販売には一般的なクーリングオフが適用されないため、一律の返品期間を自動設定しません。カレンダーアプリへのICSの取り込みは手動で、通知はそのカレンダーアプリの挙動に依存します。ページ自体は閉じている間に通知しません。更新日を反復生成する機能、端末間自動同期、証拠書類の添付、契約の解約代行は未実装です。個人情報やパスワードは入力しないでください。

## 動かし方

1. `index.html` をブラウザで開く。
2. 「期限を記録する」で内容と最終期限、準備日数を入力する。
3. 行動日・最終期限を確認して、必要に応じて `.ics` をカレンダーに取り込む。
4. バックアップ用にJSONを保存する（ブラウザのデータ削除時の消失に備える）。

## 検証

Chromiumによるブラウザ操作スモークテストを実施し、以下を確認。

1. 初期画面 → サンプル3件の追加 → 検索
2. 既存記録の編集、新しい記録の作成
3. HTML/JavaScript文字列入力がDOMの画像・スクリプトとして実行されないこと
4. 完了切り替えと状態フィルタ
5. JSON書き出し、削除、JSON復元（上書き確認）
6. ICS生成が3イベントで、CRLF区切り・75バイト以下の折り返しに適合すること
7. 日付演算（2028年の閏日、年またぎ）、無効日付・不正インポートの拒否
8. スマートフォン幅390pxで横スクロールが出ないこと、外部ネットワークリクエストがないこと

**検証の境界:** 実行環境のブラウザが `file://` と `localhost` への直接遷移を管理者制限でブロックしたため、Playwright `page.set_content()` でHTMLを読み込み、`localStorage` はテスト用の同等APIで模擬しました。つまり実ブラウザのディスク永続化・カレンダーアプリへの取り込み・OS通知・実ユーザーの需要を検証したわけではありません。ページ内操作、JavaScript構文、日時演算、JSON/ICS生成を検証しました。
