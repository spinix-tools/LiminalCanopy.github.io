# CueRest / 譜めくり設計
2026-11-28 · v1.0 · 無依存・ローカル動作

**対象**：楽譜浄書者、吹奏楽・室内楽のパート譜作成者、演奏者。段の高さと実際に手を離せる休止秒を入力し、最大ページ数内で譜めくりの不足を減らす。

## 市場・選定理由
- 日本語の [MuseScore フォーマット設定](https://musescore.org/ja/print/book/export/html/329597) では改ページを手動調整できる。[LilyPond 最適ページめくり](https://lilypond.org/doc/v2.25/Documentation/notation/optimal-page-turning.ja.html) は休符でめくるための最適化を既に実装している。日本語資料にも実務課題が現れているが、国内市場規模は未調査。
- 海外の [Dorico Pro](https://www.steinberg.help/r/dorico-pro/6.2/en/dorico/topics/setup_mode/setup_mode_layouts_c.html) はパート譜のページ・段配置を調整可能。[SheetScroll](https://sheetscroll.com/) は演奏追従のデジタル譜めくりを提供する。
- 差別化仮説：組版や演奏追従に依存せず、紙・単ページ・見開きの条件で、許容ページ数と実測休止秒による妥協案を比較できる独立した事前設計ツール。LilyPondとは機能重複があり、世界初とは主張しない。無料で試して既存浄書ソフトへ結果を反映する導線を想定。実利用・課金意向は未検証。
- 重複確認：会話内の直近案、mainとの比較で取得できた51アプリディレクトリ、リポジトリのコミット検索（譜めくり、page turn、楽譜、CueRest：各0件）。全履歴・全ソースは未照合。

## 使用法
index.html をブラウザで開く。段名、高さ（正整数）、段末休止秒をタブ区切りで入力。最大200段、60ページ。ページ容量、必要休止秒、開始側を設定して計算。JSON出力・印刷可。入力の外部送信・保存・API利用なし。

順序固定の段を連続区間に分割する動的計画法。右始まりは奇数ページ末、左始まりは偶数ページ末、単ページは全ページ末（いずれも最終頁除外）を物理的なめくりとする。評価順は不足箇所数、不足ミリ秒合計、ページ数、空き容量の二乗和。基準案は容量まで段を順番に詰める。O(P*N^2) 時間、O(P*N) 状態。

## テスト（実施済み）
- `node test.js`：小規模の改ページ全列挙との600生成ケース照合（実行不能も含む）、固定8検査、200段容量検査：合格。
- `python browser_test.py`：Playwright と /usr/bin/chromium 使用。サンプル、モード変更、JSONダウンロード、不正入力、結果無効化、リセット、390px横幅、JSエラー0・HTTP(S)要求0：合格。環境でfile://が拒否されたため、同一HTMLをset_contentで検証。実印刷は未検証。
- サンプル：12段、容量12、最大5頁、必要休止2秒、右始まり。基準4頁/不足2箇所/計4秒 → 最適5頁/不足0箇所/0秒。

## 限界
実際の楽譜ファイルの解析・組版・自動反映、反復・D.C.などの演奏順、段の途中の休止、ページ送りの物理動作は未対応。段末休止の有効時間は利用者が見積もる。ページ数増加と休止の確保を優先順に従って比較するため、実演で最適とは限らない。市場規模・収益性未検証。
