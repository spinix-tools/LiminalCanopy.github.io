# 分岐灯 / BUNKI AKARI

**2026-11-22｜無料・オフラインの分岐フォーム経路チェッカー。** 既存フォームを送受信するサービスではなく、**フォームを公開する前の論理構造を点検する**独立したMVPです。日本語を標準UIにしています。

## 対象、選定理由、競合（2026-11-22調査）

**対象:** 自治体の窓口改善担当、NPO、学校・地域団体、少人数のフォーム制作者。申請者本人のデータは取り扱わず、「質問と選択肢の設計」だけを入力します。

**国内需要の背景:** デジタル庁は[2026-10-27に自治体等向けオンライン申請サービスの本格運用開始](https://www.digital.go.jp/policies/administrative_procedures_online)を案内。行政・団体の入力フォーム設計の重要性は高まっていますが、**当アプリの直接需要、市場規模、利用意欲の証明ではありません**。

**国内競合:** [formrunの条件分岐](https://form.run/home/use/branch)は回答に応じた質問表示の変更を提供。フォーム作成から管理まで広く扱うため、単純な「条件分岐」だけでは差別化できません。

**海外競合:** [Typeform Logic Map](https://help.typeform.com/hc/en-us/articles/360057591531-Logic-Map)は分岐のグラフ表示やトラブルシューティングに対応。[Tally](https://tally.so/help/conditional-form-logic)は無料の条件分岐、プレビューとテスト手順を案内。既存製品も論理点検をある程度支援しています。

**狭い差別化仮説:** アカウント不要・質問文だけのローカル設計で、**到達不能・存在しない遷移・出口のない分岐・循環・重複選択肢を同時診断**し、150件までの回答経路をCSVで渡せること。汎用フォーム作成サービスとの正面競争ではなく、**公開前QAの小さな道具**としての継続使用を仮説とします。独自性・有料化可能性は未検証です。

## 実装機能

- 1〜30質問、各1〜5選択肢を編集。選択肢の行き先（次質問／完了）と想定回答時間を設定。質問の追加・削除、開始質問の切替。
- グラフ検査：到達不能、行先未設定、完了不能、循環辺、選択肢名の重複・空欄、長すぎる経路の警告。
- 回答者モードで選択肢をクリックして経路を試走。自己ループ等は再訪時に停止表示。
- 最大150件の経路ケース探索（経路ごと同じ質問の再訪で打切り）。完了・不明遷移・循環を区別。経路数が上限に達した場合は注記。
- 経路と指摘のCSVダウンロード、設計JSON入出力、診断メモのコピー、`localStorage`への自動保存。エスケープ付き描画、上限付きインポート。
- サンプルには意図的に自己ループ（q5）と未到達質問（q6）を収録。q5 の「まだ読んでいない」を q6 に接続すると、両警告を解消できます。

**制約:** 選択肢による明示的な分岐のみ対応。複数条件のAND/OR、自由記述による判定、非同期バリデーション、必須／任意の条件出し分け、外部フォーム製品への自動同期は未対応。経路総数が非常に多いと150件で表示・集計を打ち切ります。循環がある場合の「最長経路」は確定できないため非表示にします。構造検査は文面のわかりやすさやアクセシビリティへの適合を保証しません。

## 起動

`index.html`, `style.css`, `engine.js`, `app.js` を同じフォルダに置いて `index.html` をダブルクリック（ビルド不要）。`file://`で保存が拒否されるブラウザでは `python -m http.server 8000` などローカル静的サーバーで開いてください。CDN / 外部API / 有料サービス / ユーザー登録 / 回答者データ収集はありません。入力内容はブラウザのローカル保存領域にのみ書かれます。
