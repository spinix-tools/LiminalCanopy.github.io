# 抜けても / NUKETEMO

「担当者が急に休んだ日」を仮定し、複数役割と代行習熟度から**止まる業務**を見つける、オフライン日本語Webアプリ。公開日：2026-11-23。

## 対象・選定理由
自治会、PTA、ボランティア運営、小規模店舗など、毎年度の役割交代や欠員に備えるチーム。熊本市は**2026-04-30**に、担い手不足・負担軽減を課題とする町内自治会運営調査を公開（913人を対象、816回答）。福井市も**2026-09-30**に自治会の持続可能性を検討する2,524件の市民調査を公開。これは課題の存在を示すが、本製品の支払意思は示さない。

- [熊本市の調査](https://www.city.kumamoto.jp/kiji00370113/index.html)
- [福井市の調査](https://www.city.fukui.lg.jp/kurasi/mati/jiti/jichikai-report.html)

## 競合・差別化仮説
日本：[JICHILOG](https://jichilog.jp/)（自治会業務の引継ぎ記録）、[JICCI](https://jicci.app/faq/)（自治会の回覧・名簿など）。海外：[IqOrg](https://iqorg.com/)（職務継続性・属人化マップ）、[Process Street](https://www.process.st/help/docs/employee-onboarding/)（手順/オンボーディング）。
**仮説：** 文書整備や汎用ワークフローより前に、欠員のシナリオをその場で試し「代行候補の名前だけ」と「演習済み」を区別し、優先して演習すべき業務を出す超軽量ツールには導入余地がある。競合にも一部共通機能があるため独占的な新規性は主張しない。需要・収益性は未検証。

## 機能
`index.html` を開くだけの単一ファイル版。役割の追加/削除（実名不要）、業務の追加/編集/削除、重要度・頻度・手順、候補だけ/手順確認/演習済み、1人または複数人欠員のシミュレーション、1人欠員時リスク順位、改善事項、Undo、JSONインポート/エクスポート、CSV点検表、Markdown引継ぎメモ、ブラウザ端末保存。外部スクリプト・API・通信・課金なし。機密情報と個人情報を入力しないこと。

計算：重み = 重要度 (1/2/4) × 頻度 (1/2/3)。停止懸念 = 重みの100%、要演習 = 50%として加重リスクを表示。**これは実際の停止確率でも安全認証でもない。** 演習の入力は自己申告。

## 検証と限界
このGitHubファイルは会話内ZIPの**完全版とは別の軽量UI実装**です。完全版に対して Node.js **18/18単体テスト + 800固定シード系列**、Chromium **24/24操作項目**を合格（編集、複数欠員、インポート/エクスポート、モバイルを含む）。Github版は作成・再取得・静的確認を行い、**このGitHub版そのもののブラウザ実機操作は未検証**。完全版のブラウザテストは管理環境の制約でHTML/CSS/JSをインライン実行し、localStorageをメモリ模擬（通常のfile://起動と永続保存は未検証）。どちらも現場での技能・代行成功や安全性は別途検証が必要です。

## 使い方
1. `index.html` をブラウザで開く（必要ならローカルHTTPサーバを使用）。
2. 左欄で欠員の役割を選び、業務・代行準備を編集。
3. 出力した引継ぎメモで実際の代行演習を行う。
