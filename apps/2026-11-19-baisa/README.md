# 焙差 / BAISA — 焙煎カーブの工程差分を見比べる

2026-11-19制作。**個人焙煎家、小規模ロースタリー、焙煎教室**を対象にした無料・ローカル実行のWeb MVP。`index.html` を開いて使う。ビルド・登録・通信・課金なし。

## 選定理由と市場調査

- 日本：全日本コーヒー協会の2026-11-05更新統計によると、**2025年の国内コーヒー消費量は397,272トン（前年比99.3%）**。これは広いコーヒー市場の規模であって、本アプリのユーザー数・支払意欲を示すデータではない。https://ajca.or.jp/data/
- 日本の競合： [RoastGenius](https://roastgenius.app/) は温度記録・焙煎条件・カッピングスコアの管理を提供。[OLLA Brew Lab](https://ollabrewlab.com/ja) はArtisanなど複数形式の取り込み・RoR再生・バッチ比較を提供。
- 海外の競合：[Artisan Roast Comparator](https://artisan-scope.org/docs/comparator/) は最大10バッチの曲線比較とイベントによる時間位置合わせ、[Tandy Coffee Roast Lab](https://tandycoffeeroastlab.com/) は焙煎CSV解析と欠陥候補の検出を提供。
- 国内外に実用品があるため、**曲線比較自体は新規ではない**。世界の主要な焙煎アプリが既に深い機能を持ち、強い競争がある。

## 差別化仮説

「投入からの経過時間」「1ハゼを0秒とする比較」「**投入→黄変→1ハゼ→排出の各工程を等幅に正規化**」をワンタップで切替え、2本の曲線を比較する。時間を揃えた場合と工程比率を揃えた場合の温度差を分け、**味の良否を勝手に点数化しない**。焙煎中の機材接続を必要とせず、講座・検討会で低負担に使えるかを検証する。

## 実装機能

- バッチA/Bの手動CSV貼付・ローカルファイル読込（`time,bt`、時間は秒または `m:ss`、豆温は °C、UTF-8、カンマ・タブ・セミコロン区切りに対応）。イベント（黄変/1ハゼ/排出）を編集。
- 3方式の比較SVGグラフ、温度差（平均絶対値・最大値）、DTR差、排出温度差、工程別平均差、位置スライダー、工程別サマリー。
- CSV差分・SVGグラフ・プロジェクトJSONを出力、JSON復元、印刷、端末内localStorageでの設定保存、デモ復元。
- 入力不整合（時刻逆転・重複・イベント順異常・値域外・欠測など）をエラー表示。ライブラリ依存・外部通信・個人情報収集なし。

## テスト（2026-11-19）

- `node --test engine.test.cjs`：**16/16合格**。うち250通りの時間軸伸縮に対する工程正規化の不変性テストを含む。
- `python browser_test.py`：**30/30 Chromium操作アサーション合格**。3モード、スライダー、異常CSV復旧、CSV/SVG/JSONダウンロード、CSV/JSONアップロード、モバイル、JSエラーを確認。
- `node --check engine.js && node --check app.js` 合格。
- 実行環境ではブラウザに同一ソースをインライン展開して試験（ファイルURL直接ナビゲーションには管理ポリシー制限あり）。`file://`からの起動・OS側のファイルダウンロード処理・実プリンタ・localStorageの永続性・各焙煎機独自形式の互換性は未検証。

## 計算・利用上の限界

工程正規化は、各バッチの3区間を各33.33%に写像する**区分的時間伸縮**で、経過時間に基づくRoRや風味の因果推定ではない。線形補間を使用。平均差は揃えた比較区間101点の単純平均で、物理的な時間加重平均ではない。実際の味、焙煎の安全性、品質や焼成の良否の判定はできない。基本的に同一豆・同一センサー条件下の比較に限る。

CSVは2列の簡易共通形式であり、**Artisanなどの専用フォーマットを自動判定するものではない**。必要に応じて `time,bt` へ整理すること。扱う値の正確さは元記録に依存。変化量を「改善」と解釈せず、実際のカッピングと照合する。
