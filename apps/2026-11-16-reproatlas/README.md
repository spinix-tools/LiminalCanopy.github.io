# 再現地図 / ReproAtlas

制作日: 2026-11-16 / 日本語・ローカル保存型のバグ再現記録アプリ

## 1. 対象・選定理由

対象は小規模なWeb制作・QAチーム、個人開発者、非エンジニアのテスト協力者。バグ報告を一枚だけ作るのではなく、同じ事象の「再現」「非再現」「判定不能」を試行として残し、端末・ブラウザ・ログイン・回線の差を比べたい層を想定。

**日本:** 2026年7月15日付「バグ票の書き方」（テスター10）は、再現手順の不足が開発者との往復を生む課題を取り上げる。2026年8月16日付 WorkNihongo 記事も、環境・権限・操作順・期待／実際を分けた報告の重要性を説明。これらは需要課題の例であり市場規模・購入意欲の実証ではない。

**海外競合:** [Jam](https://jam.dev/) は録画・ログ・ネットワーク・AI要約、[Usersnap](https://usersnap.com/quality-assurance) と [Marker.io](https://marker.io/qa-tool) はスクリーンショット・注釈や技術的メタデータを扱う。[OpenJam](https://github.com/SaintPepsi/openjam) にはオープンソース・ローカル処理の強力な選択肢もある。

**差別化仮説:** 自動収録機能を追わず「同一バグの複数試行」「非再現例の保存」「条件別の実測割合」「GitHub Issue向けテキスト化」に集中する。繰り返しの検証に価値を感じる少人数チームなら選ぶ可能性がある。ただし実利用、継続率、収益化はいずれも未検証。

## 2. 使用方法と実装

`index.html` を開いてください。ビルド、外部API、アカウント、課金は不要です。

- 複数のバグ案件、タイトル検索、編集、削除
- 再現手順、期待と観察、アプリバージョン、影響度の保存
- 端末・ブラウザ・認証状態・接続ごとの個別試行の記録、削除、結果フィルター
- 再現数 / 判定済み件数の条件別比較（判定不能は分母から除外）
- Markdownプレビュー、コピー、ダウンロード、簡易伏せ字
- JSON全件バックアップ、個別エクスポート、全件置換インポート
- 小画面対応、ブラウザの `localStorage` へのローカル保存

記録された割合は**真の障害発生確率や原因の証明ではありません**。他条件との交絡、試行数・選択バイアスに注意。マスクは限定的で、ユーザーが秘密情報・個人情報を最終確認する必要があります。画面録画・外部Issue投稿・同期・通知は非実装。ブラウザデータを消すと記録も消えるためJSONバックアップを推奨します。

## 3. 検証と限界

- GitHub上の単体HTMLにソースを書き込み、再取得と主要DOM要素・イベント参照の静的検査を実施。
- 別途作成した同一コンセプトの**拡張版**は、Chromium/Playwrightで9系統（試用データ、案件操作、試行集計、マスク、JSON/Markdown入出力、検索、390pxモバイル、外部通信・JS例外監視）を通過。**GitHub掲載の軽量版とは実装が異なるため、このテスト結果を掲載版のブラウザ試験成功とは扱わない。**
- GitHub掲載の軽量版については、通常のWeb起動・実ブラウザでの永続化・クリップボードは未検証。実利用者による需要検証も未実施。

## 4. 既存作品との非重複

「ことばのクッション」（断り文句生成）、「まにあう帖」（期限管理）、「時差フェア」（会議時差調整）とは用途・主要データモデルが異なり、本作では**バグの複数試行と条件別比較**を主機能にしている。
