# かりぐみ / KARI GUMI

**行事の備品を「時間 × 数量 × 前後準備」で仮予約し、不足と代替時間を探すオフラインWebアプリ。**

## 対象・選定理由

学校・町内会・小規模イベント・研修の運営担当者。複数会場で同じプロジェクターやマイクを使う際、表計算では「同時刻に何個必要か」と返却後の片付け時間が見落とされやすい。国内に備品管理サービスが継続的に存在し、海外には多機能なレンタル・資産管理SaaSがあることから、課題自体の実在は推察できる。一方、**この無料オフラインツール固有の需要・有料転換・市場規模は未確認**。

## 競合調査（2026-11-18時点の公式掲載内容）

- 日本 **LendPort**：大学・施設向け、予約、QR貸出/返却、CSV実績。https://www.collabo-sys.jp/service/lendport/
- 日本 **KashiTe**：QRで共用品の貸出・返却を記録、無料プラン。https://kashi-te.com/
- 日本 **EDISONE**：レンタル予約、在庫管理、レンタル前後の準備日設定。https://edisone.jp/i/rental/
- 海外 **Cheqroom**：実時間の予約衝突判定、資産管理、返却記録。https://www.cheqroom.com/features/equipment-scheduling-software/
- 海外 **Booqable**：在庫カレンダー、レンタル前後のバッファ設定。https://booqable.com/features/

**差別化仮説**：予約・貸出管理そのものやバッファは既存製品にもある。かりぐみは、アカウントや担当者の個人情報を用いず、**イベント単位で複数の備品をまとめて仮配置 → 不足数・不足時間を可視化 → 全備品が同時に空く近い時間帯を30分刻みで提案 → 持ち出し表を印刷**する「開催前の計画」に用途を絞る。共同予約システムや実在庫台帳の代替ではない。

## 動作と機能

HTMLファイル index.html を開く（engine.js、app.js を同じフォルダに置く）。ネットワーク、ビルド、外部ライブラリは不要。

1. 備品名、所有数、前後それぞれの準備・片付け時間を登録・編集。
2. イベント名、日時、必要な備品と数を指定。現在の予定との同時使用ピークを計算し、超過すると予約をブロック。
3. 予約が入らない場合は、元の開始から30分刻み・最大7日後まで、時間をずらした候補を検索（最初の4件）。
4. 不足数量と時間帯、全体最大需要を表示。予定の編集・削除、持ち出し表、印刷に対応。
5. JSONファイルでエクスポート・再読込、CSVで予定一覧を書出し。端末のlocalStorageに自動保存。

計算仕様：同じ備品の要求数を、予約時間の前後に指定の準備時間を加えた**半開区間** [開始-バッファ, 終了+バッファ) で足し合わせ、最大同時使用数と在庫との差を求める。終了と次の開始が接するだけならバッファ0のときは競合しない。候補探索は近いスロットを列挙するだけで、複数イベントの全体最適化ではない。

## 制約と安全

- 1ブラウザの端末内データであり、同時更新・権限管理・貸出実績追跡・本人確認・通知・現物確認はない。共有端末にデータが残る可能性がある。
- 1～32種類の備品、最大120件のイベント、各イベント最大7日。準備時間は備品ごとに0～480分。日時は利用端末のローカル時刻。
- JSON読込では形式・数量・参照先を検査するが、読み込んだデータに含まれる既存の予約衝突は分析対象として残す。
- 入力内容は外部に送らない。不要な個人情報・秘密情報は記入しないでください。外部API、有料サービス、追跡ツールなし。
- 推計は計画上の数であり、運搬時間、物理破損、設置の安全性は保証しない。
