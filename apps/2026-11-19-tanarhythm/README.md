# 棚リズム / TANA RHYTHM — 小さな店の棚割・補充シミュレーター

2026-11-19 / MIT License / HTML・CSS・JavaScriptのみ / 外部API・アカウント・課金なし

## ターゲットと選定理由

個人商店、雑貨店、マルシェの常設棚、小規模直営店の棚割担当者。棚に何列並べると次回補充まで欠品しにくいか、商品幅・奥行・売れ行き・粗利から決めたい人向け。前回までの3D梱包・行列・撮影・調理・翻訳・入金照合・日照・堆肥・カード確率・字幕アプリとは異なる**実店舗の棚割・在庫補充**の問題を扱う。

日本市場：経済産業省が2026-04-14に発表した2025年の小売業販売額は約157.5兆円（総市場の規模であり、このアプリの市場規模・需要を示すものではない）。既存の国内棚割サービスとして日本総合システムの**StoreManager AI自動棚割**、リテイルサイエンスの**WinWinシェルフ**がある。

海外：**PlanoHero**は多店舗の棚割・フェイス数・棚在庫の自動計画を提供し、公開料金ページでLiteプラン月199ドルと表示（閲覧時点、変更可能）。**Datawiz**にも予測販売・欠品を含む棚割機能がある。したがって棚割最適化そのものは新規発明ではない。

**差別化仮説**：単一棚・数SKUの店舗担当者が、サブスク、POS連携、撮影、ユーザー登録をせずに、**補充までの日数・奥行に何個並べられるか・粗利の飽和・棚幅**を同時に触り、推奨フェイス数の理由と欠品見込みを確認できる軽量な日本語の道具。支払意思・実際の需要・競争力は未検証。

## 実装機能

- 棚の幅/高さ/奥行/補充サイクルと、商品幅/高さ/奥行/1日平均販売数/個粗利/最低・最大フェイスを編集
- 手動で列数の増減、商品追加・削除、棚の正面配置表示、寸法超過アラート
- 予測粗利、店頭在庫、補充までの需要、売り逃し、欠品リスクの比較
- **最適化**：商品別の列数候補を複数選択ナップサック法で探索し、想定期間の棚内在庫から得られる粗利を最大化（最小・最大フェイス制約あり）
- 提案反映、JSON保存/読込、CSV出力、印刷、ブラウザ内の状態保存（localStorage）
- サンプル5商品入り。レスポンシブ画面。ネットワークアクセス不要

## 起動

4ファイル `index.html`、`style.css`、`engine.js`、`app.js` を同じフォルダに置き、`index.html` をブラウザで開く。ローカルWebサーバーで配信してもよい。ダウンロードに新たなAPIキー等は必要ない。

## モデルの前提と限界

- 1段の棚だけを計算。商品は正面向き、回転・積み重ね・棚内補充・補充遅延・販促効果・賞味期限・棚割順序の売上差は考慮しない。
- 奥行方向の個数 = `floor(棚奥行 / 商品奥行)`。店頭在庫 = `奥行個数 × フェイス数`。
- 期間需要 = `1日平均販売数 × 次回補充までの日数`。期間販売数は `min(期間需要, 店頭在庫)`。予測粗利 = `期間販売数 × 単品粗利` の合計。
- 各商品の幅は**0.5cm単位に切り上げ**て最適化し、物理的に棚をはみ出す案を生成しない。端数による未使用幅が発生することがあるため、連続幅の厳密な全体最適とは限らない。
- 需要は確率分布ではなく期待値のみ。欠品見込みは確率でなく単純な数量差。POS履歴がない商品は販売予測値を手入力する必要がある。集計上の不足数量は小数を許す。
- 不正・重複IDや過大な入力を検査。商品名はHTMLエスケープし、CSVの式注入を抑止。データ送信なし。
