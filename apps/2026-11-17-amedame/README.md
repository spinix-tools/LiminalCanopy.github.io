# あめだめ / AMEDAME ☔

**雨水タンクの「何リットルなら足りるか・どれだけあふれるか」を、同じ月降水量でも異なる降り方で比べるオフラインWebアプリ。** 2026-11-17制作。

## 対象と選定理由

庭への散水・打ち水を目的に雨水タンクを検討する個人、住宅リフォーム事業者、地域活動団体。日本では2026年の雨水タンク導入助成の公表が続いており、製品を選ぶ前に貯水容量を手軽に検討する動機があると判断した。例えば川崎市は2026年5月25日開始の購入補助を2026年4月21日に公表、品川区は2026年10月16日更新の設置助成を案内。**助成の存在は需要の可能性を示すが、ユーザー数や有料化余地を証明しない。**

## 国内・海外の競合（確認 2026-11-17）

- 日本：雨水タンクメーカーPanasonicは利用量・節約例を紹介し、自治体は制度を案内。利用者にとって容量検討と助成確認が別々の作業になる。
- 海外：RAINFAL（Texasの長期日次降雨データによるfirm-yield分析）、Holly's Homestead（月次需給シミュレータ）、Kalkmi（日別雨水タンク収支）、ToolSorcerer（期間ごとに貯水・不足・あふれを計算）。**単純な貯水量計算、日別収支、タンク比較そのものは既存機能**であり、独占的な新規性は主張しない。

## 差別化仮説

**日本語・登録不要・外部通信不要で「月別降水量の合計が同じでも、降る日が集中するとどう変わるか」を3種類の仮想配分で即比較し、容量ごとのカバー率の最悪値を表示する。** 月量しか入手できない初期検討にも使いやすくする。需要、比較優位、継続使用は未検証。

## 機能（動作するMVP）

1. 屋根の水平投影面積、集水効率、タンク容量、年初貯水量、日常・夏季使用量の設定。
2. 月別雨量（12か月）から日別雨量を生成：毎日分散、月4日集中、月2日集中。**架空の例示値**を同梱（気象平年値ではない）。
3. 日次の水収支モデル（流入→溢水→使用）で、利用量の充足率・不足日・最長不足連続日・あふれた量・タンク残量グラフを表示。
4. 任意の最大8容量を3降雨パターンで比較し、カバー率の下限を表示。表の容量をクリックして詳細表示。
5. 厳密に1年間すべての連続日付を含む日別CSV（`date,rain_mm`）の取込。取込時は仮想配分ではなく実測1系列で比較。年・日付の欠落、重複、負値を拒否。
6. CSVひな型、結果CSV、設定JSON（読込・保存）、ブラウザ内自動保存、印刷。ユーザー情報送信・有料API・外部依存なし。

## 実行方法

`index.html` をブラウザで開く。`engine.js` と `app.js` は同じフォルダに置く。ビルドやサーバーは不要。ソースはすべてJavaScript/HTML/CSSで、CDN/外部フォント・トラッカーなし。

## 計算・限界

- 基礎式：`流入L = 降雨mm × 屋根水平投影面積m² × 集水効率`（% は100で割る）。1mm×1m² = 1L。
- タンク残量は年初貯水率から開始し、各日に集水→容量を超えた分を溢水→当日利用量を引いて更新する。6～9月の需要はユーザーの倍率を適用。
- 日別の生成規則：均等配分＝その月の毎日、月4日＝4/11/18/25日、月2日＝5/20日に均等集中。同じ月別の合計を保持。**雨の分布は予報・過去実測ではなく思考実験。**
- 簡易モデルのため、降雨と使用の時刻、屋根以外の損失・初期雨水分流、蒸発、凍結、取水不能水量、配管能力、水質、維持管理、設置安全性、地域の条例・助成条件は評価しない。飲用判断・防災用水安全性・設計保証には使えない。
- ブラウザのローカルストレージには設定数値のみ自動保存。取り込んだ実測CSVは自動保存しない。JSON保存時のみ任意で日別値もファイルに含める。

## テスト結果（2026-11-17）

- `node --test engine.test.cjs` → **39/39 成功**。雨量の月合計保存、閏年、入出力、超幾何ではない水収支の保存則、容量感度、CSVの欠損・重複など。
- `python browser_test.py` → **39/39 操作チェック成功**（シナリオ切替、編集、エラー表示、表選択、CSV/JSON入出力、実測CSV、モバイル表示）。`desktop.png` / `mobile.png` はテスト時に採取した実画面。
- **制約：** 管理環境でChromiumの `file://` ナビゲーションが `ERR_BLOCKED_BY_ADMINISTRATOR` となったため、ブラウザには実HTML/CSS/JSを直接挿入し、localStorageのみ簡易モックを用いた。実URL配信と端末での永続化動作は未検証。物理的な設備試験も未実施。
