# 時差の借り / JISA NO KARI

**2026-11-17 / MVP** — 時差による定例会の「負担の偏り」を、4〜8週単位で可視化する日本語Webアプリ。ユーザー名、カレンダー連携、APIキー不要。

## 対象・選定理由

日本から海外の共同研究・制作・顧客折衝を行う2〜6拠点の小規模チーム。国際会議の調整は時差・夏時間で面倒になる。単発会議の候補比較ツールは多数あるが、**毎回同じ拠点が深夜・早朝を引き受ける問題**に定量的に取り組む余地があるため選定。市場規模と課金需要は未調査・未検証。

## 競合（2026-11-17確認）

- 日本： [tools-muchuu 時差計算ツール](https://tools.muchuu.net/tools/time-diff-scheduler/) は2拠点・勤務時間重複を表示（ページ更新日2026-09-30）。[Meetpicker 日本語](https://meetpicker.com/ja/) は複数都市の勤務時間と会議案内、夏時間を扱う。[Plainkit](https://tools.motty.jp/ja/overlap/) も複数都市の可視化・現地時刻・Google Calendar追加に対応。従って「日本語」「複数都市」「DST対応」だけでは独自性にならない。
- 海外： [World Time Buddy](https://www.worldtimebuddy.com/) と [timeanddate Meeting Planner](https://www.timeanddate.com/worldclock/meeting-help.html) は日付ごとの時間帯比較・ICS等に対応。[SavvyCal](https://savvycal.com/features/availability) は予約・可用性・チーム日程調整に強い。

## 差別化仮説

**単発の共通空き時間探索**ではなく、複数週にわたる拠点別の勤務時間外・深夜・週末負担を数値化し、総負担が小さい案と最大負担の偏りが小さい案を並べて比較する。個人名・アカウント・外部カレンダー・料金不要の端末内試算に集中。類似製品に同種の機能が無いことまでは確認していない。

## 実装済み

- 2〜6拠点のタイムゾーンと現地勤務時間、初回日、会議30/60/90分、1〜8回の週次会議を設定
- IANAタイムゾーン情報に基づく夏時間・日付跨ぎの時刻変換、30分刻みの候補列挙
- 15分単位の負担点（勤務外+3、深夜+9、土日+12、昼の微小な調整）
- 各週で総負担を最小にする案と、累計負担の最大値・範囲を抑えるビーム探索案（近似）
- 各都市の現地時刻、負担・深夜・週末時間の表示、テキストコピー、CSV、UTC版ICS予定の出力
- 設定の `localStorage` 保存とJSON書き出し・読み込み

## 実行・テスト

`index.html` をブラウザで開く（または `python -m http.server 8000` でローカル配信）。依存パッケージ、ビルド、API、ログインなし。

- `node --test engine.test.cjs`：**26/26 合格**。夏時間移行日の欠落／重複時刻、30分時差、日時と入力検証、週次負担、ICS/CSV等を検証。
- `python browser_test.py`：**24/24 合格**。ChromiumでHTML・JSを直接読み込み、登録・編集・削除・計算切替・ダウンロード・設定復元・モバイル画面を操作。
- **環境制約**：ChromiumがHTTP/fileページ遷移を管理者ポリシーで拒否するため、ブラウザテストはJSを注入し `localStorage` を模擬。実サイト配信と実ブラウザの永続化・端末差異は未検証。Node計算ロジックとデータ出力は実コードをテスト。

## 制限・安全

ICSは会議の**提案**であり参加者同意や予約を意味しない。各国祝日、休暇、既存カレンダー予定、繁忙期、個人の好みは自動収集しない。ビーム探索は大域的な最適解を保証せず、負担点の重みは仮説である。タイムゾーンの規則はブラウザ/NodeのIntl環境に依存する。機密情報・氏名を入力する必要はない。入力情報は外部送信されない。MIT License。
