# CropAnchor — 共通トリミング監査

## 対象・選定理由（2026-11-28）
ECの商品画像、広告制作、SNS運用、レスポンシブWeb制作担当者。単一の素材を複数の比率で使い回すと、中央クロップで文字・ロゴ・商品が欠ける。日本のFitlyとEsolab、海外のCropDen、ToolAcre、Adlyの既存サービスから、この作業への需要の兆候を確認した。利用者数・市場規模・支払意思は未調査。

- 日本: [Fitly](https://fitly.pics/image-resize/)（SNS向けリサイズ・実寸プレビュー）、[Esolab](https://esolab.co.jp/tools/image-crop/)（比率指定・画像切り抜き）
- 海外: [CropDen](https://cropden.com/)（サイズ別セーフゾーン）、[ToolAcre](https://toolacre.com/tools/social/)（複数比率と位置調整）、[Adly](https://landing.getadly.com/en/tools/social-safe-zone/)（中央クロップの検査）

## 差別化仮説
複数の重要矩形と出力比率から、CSS object-position の共通許容区間を計算する。完全保護不能なら、全出力・全矩形の最大辺欠け量（元画像px）を最小化する。個別のクロップ位置を試す手間を減らす。競合の全機能や世界初であることは未確認。初期仮説は画像素材の使い回し・CSS実装への引継ぎ用途。

## 起動・機能
index.html をブラウザで開く。外部依存なし。PNG/JPEG/WebP（20MB・2400万画素以内）をローカルで読み込み、画像上のドラッグまたは数値で最大20保護領域を設定。最大8出力（各辺4096px以下・400万画素以下）を比較し、最適アンカー、CSS、PNG、JSONを生成。サンプルは中央2/3出力完全保護、最大35px欠け。最適化後3/3、0px。共通X許容範囲は約56.73〜98.08%、Yは0〜100%。

## 計算・検証
cover後の元画像上の可視幅をC、元幅をL、保護区間を[P,R]とすると、アンカーaの可視範囲は[(L-C)a,(L-C)a+C]。許容欠けdについて(R-C-d)/(L-C) <= a <= (P+d)/(L-C)を全条件で交差する（余剰0は別処理）。X/Y独立、実行可能な最小dを二分探索。
- `node test.cjs`: 固定5件、独立した一次関数上包絡線の交点全探索との400ケース照合、全合格。
- `python test_browser.py`: Chromiumで初期表示・最適化・JSON/PNGダウンロード・不正入力・画像取込・ドラッグ・390px幅確認、全合格。JS例外・外部HTTP要求0件。環境制限により同一HTMLをインライン読み込み。テストにはNode.js、Python PlaywrightとChromiumが必要。

## 制限と安全性
矩形の最大辺欠けを評価し、面積損失・文字可読性・UI重畳・サービス固有の自動クロップ・画素丸め・画質は保証しない。比率は一般的な例で公式仕様ではない。画像や入力は端末内だけで処理し、保存操作時のみダウンロード。個人情報を含む画像は使用しない。外部API、有料サービス、追跡なし。既存の直近10案と専用ブランチ差分51ディレクトリ、関連4キーワードのコミット検索を確認し、明確な重複なし（全既存ソースの網羅照合は未実施）。
