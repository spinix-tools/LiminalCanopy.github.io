# あいだ割 / AIDA-WARI

途中参加・早退がある合宿、グループ旅行、シェア滞在の費用精算を「参加日数×負担係数」で見える化する、完全ローカルの日本円専用Webアプリ。**`index.html` を開くだけで使用できます**（ビルド・登録・外部API不要）。

## 誰の、どんな課題を解くか

- **想定ユーザー**: 合宿・友人旅行・ワーケーション等で、参加日が異なるメンバーの共通費を立て替える幹事。
- **選定理由**: 観光庁の2026-04-30発表では、2025年の日本人国内旅行消費額は26兆7,845億円（前年比6.5%増）。グループ精算アプリの利用母数となり得る大きな周辺市場がある。ただし、この統計は本アプリ固有の需要を直接示さない。
- **国内競合**: Trispend（旅行費の日割り、オフライン利用、立替精算、複数通貨に対応すると紹介されている）、TabiWari（子ども等の負担係数、送金回数圧縮）など。
- **海外競合**: Splitwise（均等・不均等割、債務簡素化）、tricount（カスタム配分、オフライン記録、外貨対応）。**不均等按分やオフラインは独占的な新機能ではない。**
- **差別化仮説**: 各人の「滞在期間」と各支出の「対象期間」を重ね、参加日数と負担係数により自動按分した根拠（日数・金額）を一画面で確認できる、日本語・1円丸め・完全ローカルの“合流／離脱”特化ツールにする。一般的な複雑な精算アプリより操作と説明の負担を減らせるかを検証する。

## できること

1. 参加者の名前、参加初日・最終日、係数（例：子ども0.5）を登録・編集。
2. 立替した人、金額、費用対象期間、対象参加者を設定して支出を追加／編集／削除。
3. 期間重複日数×係数で費用を按分。円未満の端数は最大剰余方式で配分、**負担額合計＝支出額**を保証。
4. 各人の立替／負担／送金済額を反映した残高と、送金件数を抑える貪欲な候補を表示。
5. 「送金済み」の記録と取り消し（**実際の送金操作は行わない**）。
6. JSON書出・読込、UTF-8 BOM付きCSV内訳、精算文コピー、印刷、ブラウザ内自動保存。
7. 初期サンプルデータ、画面幅対応、入力バリデーション、JSON読込時の形式チェックとHTMLエスケープ。

### 計算ルールと注意

- 開始日・終了日は**両端を含むカレンダー日数**。ホテルのチェックイン／アウトの泊数がそのまま自動で求められるわけではない。**対象とする宿泊日のみ**を支出の期間に設定する。
- 本アプリは**日本円の整数**のみ。FX、実際の支払い、レシートの真正性、税務処理は行わない。
- 日割りは**支出期間に均等に費用が発生する**仮定。定額の個別チケットなどは個別日・対象者を指定する。共同費の妥当性は当事者で合意すること。
- 送金候補は残高を打ち消す貪欲な割当で、厳密な最小送金回数を保証しない。
- データは`localStorage`に保存される。ブラウザの削除・ストレージ制限で失われ得るため、JSONで手動バックアップすること。氏名等は入力せずニックネーム推奨。
- CSVの文字列がスプレッドシート式として解釈されるのを防ぐため、危険な先頭記号をエスケープする。

## 検証

- `python test_browser.py` : Playwright + Chromiumの自動操作試験。**30/30パス**。`file://`直接遷移が管理環境で拒否されたため、同一HTMLを`set_content`で投入して実行。localStorageはモックのため、ブラウザ実環境での永続化は未検証。
- 入力編集、支出追加・削除・編集、端数配分、送金記録／取消、CSV/JSONダウンロード、模擬保存／再ロード、390pxモバイル画面の横スクロール欠如を検証。
- `desktop.png`、`mobile.png`はChromiumで取得した画面。
- 未検証：通常の`file://`直接起動、実配信環境、JSONの実ファイル再読込、実機印刷、複数端末同期、実利用者へのユーザーテスト。需要・収益性は未実証。

## 設計・データ

単一HTMLで外部依存ゼロ。HTML/CSS/JavaScriptは`index.html`に同梱。データ形式は`{members,expenses,transfers}`、各エントリに独立IDを付与。アカウント認証・通信・ユーザーデータ収集は実装していません。
