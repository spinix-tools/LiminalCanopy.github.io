# 帯巡 / BANDMEGURI — 2026-11-24

アマチュア無線コンテストの個人参加者・クラブの練習担当者向け、限られた運用枠の配分を比較するWebアプリ。`index.html` をブラウザで開くだけ。日本語UI、通信・登録・外部API不要。

## 市場と選定理由
- 国内：JARLの100周年記念アクティビティコンテストは2026-06-01〜2027-05-31に開催。[JARL規約](https://www.jarl.org/Japanese/1_Tanoshimo/1-1_Contest/activity.html)。[フィールドデー規約](https://www.jarl.org/Japanese/1_Tanoshimo/1-1_Contest/fd_rules.html)には得点×バンド別マルチの計算がある。
- 海外：[CQ WW公式統計](https://www.cqww.com/stats.htm)では2025年にSSB・CW合計19,005件のエントリー（人数ではない）。いずれもアプリ需要の直接証拠ではない。
- 競合：[zLog令和版](https://use.zlog.org/manual/)はコンテストログ、[LZ2XA](https://lz2xa.com/planner/)は時間別バンド・伝搬計画、[Contest Rate Planner](https://tools.nears.me/contest-rate-planner/)は運用レート・スコア試算を提供。
- 差別化仮説：同じ運用計画を通常・弱条件で評価し、バンド別マルチの重複、稼働枠と変更上限を考慮した最悪スコア最大化を、通常優先と並べて比較。クラブ5組で事前計画の使いやすさ・再利用意向を測るのが次の検証。優位性・収益性は未検証。
- 専用ブランチの196ディレクトリ名と関連5件のREADME冒頭を確認。Wi-Fi配置・自転車変速計画等とは対象が異なる。全既存コードの精査は未実施。

## 操作・モデル
1〜8個の等長枠、最大3バンド（7/14/21 MHz）、休憩、稼働・変更上限を設定。各セルの通常・弱条件に「得点:記号」（例 `12:ABC`）を入力。マルチは架空A–Lで、同じバンド内の重複のみ除外。全配分を探索（最大65,536通り）、通常最大と2条件中の最小スコア最大を比較する。同点は他方の指標、変更の少なさ、稼働枠の少なさの順で決定（最悪優先の次点指標は通常スコア）。休憩前後でもバンド変更を数える。CSV・印刷・入力検証・サンプル復元・スマホ対応。個人識別情報の入力欄なし。

サンプル（6枠・稼働4枠・変更2回まで）：1,549通り。通常優先は通常1,925点／弱96点、最悪優先は通常968点／弱872点。実測ではない。

## 検証・限界
- `node test.cjs`：固定アサーション、独立した4進数列挙＋Setモデルとの照合（乱数180件およびサンプル）合格。
- `python test_browser.py`：Chromium/Playwright（実HTMLのインライン実行、環境のfile://制限のため）。入力エラー、再計算、CSV、ゼロ稼働、最大探索、390px幅、JS例外・外部HTTP要求ゼロを確認。
- 得点・マルチは手入力の確定シナリオ。確率、電波伝搬、交信相手の重複・時間依存の得点、個別大会規約、公式ログ提出、無線機制御、実際の成績は対象外。2条件以外への頑健性は保証しない。実利用・市場需要は未検証。
