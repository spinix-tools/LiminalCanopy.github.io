# 抜検ナビ / NUKIKEN NAVI

2026-11-22 制作。**有限ロットの抜取検査リスクを数値で可視化し、その計画で実際に抽出番号を発生させ、全件確認後に合否を表示する**、日本語・登録不要・ローカル動作のWebアプリ。

## ターゲット・選定理由

数十～数千点の部品、印刷物、雑貨などを検査する小規模メーカー、購買・受入検品、学校の品質管理教育。中小企業庁の[2025年版中小企業白書](https://www.chusho.meti.go.jp/pamflet/hakusyo/2025/chusho/b1_1_5.html)は未デジタル化の企業が残ると報告。中小機構の[生産工程スマート化診断](https://www.smrj.go.jp/sme/digital/smart/)でも品質管理・省力化・見える化を課題として扱う。これは周辺需要の根拠であり、当アプリの利用者数・売上・支払意欲の直接証拠ではない。

## 日本・海外の競合（2026-11-22 調査）

- **国内:** [抜取検査計算機 sampling-calc](https://github.com/kotaooka/sampling-calc) は超幾何分布による合格確率、複数計画のOC/AOQ/ATI、不良率推定、逆設計まで提供する強い競合。[Mahiro Apps 抜取検査計算](https://mahiroapps.com/sampling-inspection-calc)もJIS表引き・OC曲線対応。**統計計算自体に独自性はない**。
- **海外:** [MetricGate Acceptance Sampling](https://metricgate.com/docs/acceptance-sampling/)は有限ロットの厳密な合格確率や検査量を提供。[iFactory AQL Sampler](https://tools.ifactoryai.com/tools/aql-sampler)は判定記録、計画印刷等を提供。検査結果の記録自体も既存機能。
- **制度:** [ISO 2859-1:2026](https://www.iso.org/standard/2859-1) は2026年1月発行の計数値検査の国際規格。本アプリは規格表や切替規則の再現・規格適合を**主張しない**。

**差別化仮説:** サンプル設計と現場作業の間の「実物の抽出番号」「個別の良/不良/保留の記録」「未検査なら判定しない」を、単純なローカル日本語UIで一続きにすること。高機能な品質管理システムの代替でなく、現場導入前の独立した簡易補助。実需・競争優位・収益性は未検証。

## 完成MVPの機能

1. ロット総数2～100,000、抽出数1～500、許容不良数0～n、良品側・不良側の仮定率、検査時間を編集。有限ロット・無復元の**超幾何分布**で両側の誤判定リスクとOC曲線を表示。
2. 不良側を合格させる確率の目標を設定し、現許容不良数のもとで**500件以内の最小抽出数**を全探索。達成できない場合は不可と表示。
3. ブラウザの暗号学的乱数（利用可能時）で **Floyd法**による非重複抽出番号の生成。利用不可なら擬似乱数へフォールバックし表示。
4. 番号ごとに「良」「不良」「保留」を記録。**保留が1件でもあれば合否は未確定**。抽出条件変更時には以前の抽出を無効化。
5. CSV検査表ダウンロード、JSON書出し・復元、ブラウザ内自動保存、印刷、モバイル画面。入力データの外部送信なし。

## 起動とテスト

`index.html` と `style.css`、`engine.js`、`app.js` を同じフォルダに置き、ブラウザで `index.html` を開く。追加のパッケージ、APIキー、CDN、サーバーは不要。1ファイルで扱いたいときは `standalone.html` を開く。

```
node --test engine.test.cjs
python browser_test.py
```

- `node --test`：**11/11合格**。少数ロット全列挙を独立組合せオラクルと照合（2～19個、全不良総数/抽出数/許容数）、危険率の単調性、抽出の一意性、記録判定、CSV、不正入力を検査。
- Chromium：**33/33合格**。計画計算・グラフ・抽出番号・個別判定・CSV/JSON・変更時無効化・復元・感度探索・スマートフォン幅を操作。JS例外ゼロ、外部HTTP通信ゼロ。単一HTML版の追加スモークも4/4合格。
- **ブラウザテストの制限:** 管理環境は `file://` とローカルHTTPのナビゲーションを拒否。実際の `index.html`・CSS・JSを `set_content` とインライン注入で動かし、`localStorage` をメモリ実装に置き換えた。従って`file://`での直接起動、実ブラウザの保存持続性、GitHub配信は未検証。検査結果はシミュレーションであり実物の欠陥検出能力も未検証。
- ZIPのCRC/整合性は別途検査。

## 計算と安全上の限界

仮定不良総数 `D = round(N × 不良率/100)` とし、`P(合格) = Σ_{k=0}^c [C(D,k) C(N-D,n-k) / C(N,n)]` をログ階乗で計算。有限ロットでは不良率の小刻みな変化に対して階段状になる。欠陥を完全に見つけられること、無作為抽出の前提、同一ロット内の判定基準の一貫性を仮定する。現物を番号で一意に識別できず抽出できないなら妥当性は損なわれる。**ISO/JIS/契約に準拠した合否判断、重大欠陥の安全検証、品質保証には使わないこと**。外部規格や顧客指定を優先し、担当責任者が計画を承認する必要がある。
