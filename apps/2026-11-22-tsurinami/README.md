# つり波 / TSURINAMI

小規模なマルシェ、文化祭、即売会の出店者向け。「当日、お釣りが尽きるか？」を、商品価格・金種別準備枚数・支払い傾向・来客順序を組み合わせて検討する、日本円専用の登録不要Webアプリ。

## 調査・選定理由（2026-11-22）

経済産業省が2026-03-31に公表した2025年のキャッシュレス決済比率は58.0%（**金額ベースの国内指標**。現金決済件数が42%という意味ではない）。対面販売での現金管理はなお検討に値する。[一次資料](https://www.meti.go.jp/press/2025/03/20260331006/20260331006.html)。

国内競合：[お釣り電卓](https://apps.apple.com/jp/app/id367338685) は個々の釣り銭を計算し、[釣銭準備金の計算](https://ta5k.com/tools/industry/tsurisen-kinshu) は取引件数の仮定から金種の目安を出す。国外競合：[TillClosr Starting Cash Bank Float Calculator](https://tillclosr.com/tools/starting-bank-float/)（2026-09-08更新）は平均的なお釣りから準備額を推定し、[MoneyDeck](https://moneydeck.io/tools/cash-drawer-calculator) は金種別レジ締めに特化する。販売者向けの[釣り銭準備スプレッドシートの有料販売例](https://booth.pm/ja/items/9166590)もあるが、需要規模や収益性を示すものではない。

**差別化仮説:** 単発計算や平均値による推奨でなく、具体的な商品価格と支払いパターンを設定し、有限枚数の金種が来客順序によっていつ不足するかを繰り返し比較できること。市場適合性・支払意思・予測精度は未検証。

## 使い方

index.html をブラウザで開き、初期金種・商品と重み・お預かり率・現金客数を設定し「シミュレーション」を押す。乱数シード固定で同条件を比較できる。結果を見て金種を調整、模擬会計、JSON/CSVエクスポートなどが可能。利用にAPIキー・アカウント・個人情報は不要。外部ネットワーク通信なし。

## 実装と制限

GitHub版は単一HTMLの軽量版で、試算と金種調整をすぐ試せる。**可読な完全版ソース（engine.js / app.js / style.css / standalone.html）、テスト・画面画像は同一回のZIP成果物に収録**。完全版のNode.jsテスト17/17、乱数条件の現金保存800ケース・小額組合せの総当たり照合300ケース、Chromium操作29/29を確認。ブラウザテストは管理環境の制限により同一ソースのインライン展開で実施（通常のfile://直起動・永続保存・実運用は未検証）。**上記試験はZIPの完全版に対するもので、GitHub軽量版の試験ではない**。

各会計は単品購入、支払パターンは「ちょうど」又は紙幣単位への切り上げ、現金客数はユーザー入力。結果は設定依存のシナリオであり、実需予測・釣り銭保証・正式なPOSや税務記録ではない。
