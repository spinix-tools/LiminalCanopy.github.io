# 箱棚 / HAKODANA

**制作日：2026年11月16日（JST）** · インストール・登録不要 · OpenAI API不要

「箱の外側3辺は小さいのに商品が入らない」「小さな箱でも重量超過で次のサイズ帯になる」「手元の箱代を含めるとどれが有利か」が、別々の計算になっている問題を一画面で検討する、**単品梱包の意思決定ツール**。

## 想定ユーザーと選定理由

フリマ出品者、小規模EC事業者、個人発送を頻繁に行う人。発送前に商品の寸法だけでなく、緩衝材込みの収納可能性・箱の外寸・重量・利用者自身の送料と箱代を比較したい層を想定しています。これは需要の**仮説**であり、ヒアリングや実使用量の検証はまだありません。

## 市場・競合（2026-11-16確認）

- **国内の公式基準**：ヤマト運輸の宅急便は梱包後の外側3辺と総重量の両方でサイズ区分が決まり、60〜200サイズの表が公開されています。特に重量の超過で料金帯が変わる可能性があります。 [ヤマト運輸・サイズ](https://www.kuronekoyamato.co.jp/ytc/customer/send/search/payment/size/)
- **国内の需要・競合**：メルカリの靴類発送ガイドは梱包後の寸法と資材込みの重量を明示しています。また [MercaFee](https://www.mercafee.com/) は国内14サービスの送料・梱包コスト比較を提供しており、**送料比較自体は新規性がありません**。 [メルカリ公式発送ガイド](https://help.jp.mercari.com/guide/articles/86/)
- **海外の競合**：[PackCalcs](https://packcalcs.com/box-size-calculator/) は内寸・外寸・緩衝材・積載設計を、[CalculatorDaily](https://calculatordaily.com/box-fit-calculator) は6方向の回転可否を提供します。**回転判定自体も独自機能ではありません**。

**差別化仮説：** 送料比較サイトや1回限りの計算機ではなく、利用者が実際に持っている箱を名前・外寸・板厚・重さ・単価でストックし、商品ごとに収納の可否と配送区分、箱代を含めた支払額を再計算できることが選択コストを下げる。類似の在庫管理サービスがある可能性があり、競合網羅性は未確認です。効果や事業性の実測も未実施です。

## 実装した操作

1. 商品の長さ・幅・高さ・重量、緩衝材の厚さ／重量、上下固定の有無を編集。
2. デモ在庫5箱を編集・追加・削除。箱の外寸から板厚の両側分を引き、収納可能な**内寸**を計算。
3. 6方向（上下固定では2方向）で商品が収まるか判定。残り内寸を軸別に表示。
4. 箱の外側3辺と梱包後の重量から、ヤマト通常宅急便のサイズ・重量帯に対する目安を判定。
5. 配送料をサイズ別に**自分で入力**。全候補分の料金が分かると、送料＋箱代の総額で順位を付ける。不明な送料があれば**最安とは表示せず**サイズ帯優先で表示。
6. localStorageで端末内保存、JSONバックアップ出力・取り込み、結果テキストのコピー。

`index.html` と `engine.js` を同じフォルダに置いてブラウザで開けば動きます。ホスティング時にもバックエンドやアカウントは必要ありません。データを外部へ送信する処理はありません。

## 計算の範囲と注意点

- 1回に**直方体1個**。斜め配置、異形物、複数商品の詰め合わせ、圧縮、段ボールの強度や破損防止は計算しません。
- 料金は固定表示せず、利用者が公式運賃を確認して入力します。各配送サービスの全条件・指定資材・長辺上限・品目制限・運賃改定を完全には網羅しません。
- ヤマトの通常宅急便の表を参考に、3辺合計・重量・一辺170cm以下のみの簡易判定を行っています。上下逆さまにできない荷物の1辺100cm制限など、個別条件の検査はしていません。配送可否と運賃は配送業者に確認してください。
- 「箱代＋送料」に緩衝材購入費、人件費、保険料、距離による運賃変更などは自動で入りません。緩衝材重量は入力できます。
- ブラウザのストレージを消すと在庫が失われます。必要ならJSONでバックアップしてください。

- `node --test engine.test.js`：**9/9成功**。回転、上下固定、内寸、重量での区分繰り上がり、上限、価格未設定時の誤判定防止、入力検査など。
