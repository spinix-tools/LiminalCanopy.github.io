# 収穫なみ / SHUKAKU NAMI

小さな家庭菜園で「一度に採れすぎる／採れない」をならす、**食べ切り量を目標とした作付けリレー計画**。2026-11-21制作。`index.html` をブラウザで開く。アカウント・APIキー・ビルド・外部通信不要。

## 誰の、どんな課題？

ターゲットはプランター2〜5個、または小区画の家庭菜園を持ち、収穫の偏りを避けたい家庭・市民農園利用者。収穫量を食分（副菜1人前相当の任意単位）で見積もり、**週次の食べ切り目標**を先に決めて不足／過剰を示す。

## 日本・海外の需要／競合（2026-11-21確認）

- 日本: タキイ種苗『2026年 家庭菜園に関する調査』（2026-03-04）は20〜69歳400人の調査で、小スペース栽培への関心や時間・場所・費用の障壁に言及。[出典](https://www.takii.co.jp/info/news_260304.html) ※国内全人口の利用者数を示すものではない。
- 日本: 矢野経済研究所（2026-06-24）は**国内総種苗市場2025年度2,282億円見込み**と公表。ただし生産者向け等を含む市場であり、本アプリのTAMには使えない。[出典](https://www.yano.co.jp/press-release/show/press_id/4132)
- 国内競合: [菜園ナビ](https://matome.saien-navi.jp/about_saiennavi)（栽培記録・スケジュール・コミュニティ）、[家庭菜園ごよみ](https://apps.apple.com/jp/app/id6792202223)（地域別作業カレンダー）。
- 海外競合: [Seedtime](https://seedtime.us/) は栽培カレンダー、区画設計、継続播種を提供。[Gardentasia](https://www.gardentasia.com/) は区画設計・輪作・継続播種にも対応。これらは幅広い機能を有する強い競合で、「作付け提案そのもの」が新規ではない。

**選定理由**: 記録・栽培暦とは別に、家庭の週当たり食べ切り量を計画の評価関数へ直接組み込む余地があると考えた。**差別化仮説**は「一定の食分目標に対する不足と採れすぎを見ながら、狭い区画で次の1作を提案できる、超小型・完全ローカルな日本語Webアプリ」。調査からヒットや収益性が確定したわけではない。検証には菜園利用者インタビュー・栽培実測が必要。

## 実装機能

- 区画の追加・削除・改名、作物プロファイル（収穫週・収穫期間・食分・種まき適期・科）の編集・追加・削除
- 8〜52週のタイムライン、作付け追加・日付変更・削除・棒の選択、各週の収穫量・不足・過剰をSVG表示
- **次の一作を自動提案**: 区画の占有重複、種まき月、同科の直後作付け（12週目安）を避け、目標不足減少 − 0.45×余剰増分を最大化する候補を全探索、ワンクリックで採用
- 区画衝突・設定種まき月外・同科直後作付け・表示期間超過の警告
- CSV（UTF-8 BOM）、JSONエクスポート／インポート、ブラウザ内自動保存、印刷

**モデルの限界**: 1区画=同時に1作物、収穫週は各週同じ食分とし、収量・生育期間は仮値。地域の霜、日照、土壌、肥料、病害虫、実際の混植、品種差、天候・気温は計算に含めない。同科12週警告は簡易ヒューリスティックで、十分な輪作間隔や栽培の安全性を保証しない。実際の種袋表示・地域指針を優先する。

## ファイル・実行

`index.html`, `style.css`, `engine.js`, `app.js`: アプリ本体。`engine.test.cjs`, `browser_test.py`: テスト。`desktop.png`, `mobile.png`: 画面画像。`LICENSE`: MIT。`index.html`を開けば通常のブラウザで使用できる構成。データはその端末の `localStorage` に保存する設計で、JSON書き出しでバックアップできる。アプリからの外部リクエスト・有料API・個人情報収集はない。
