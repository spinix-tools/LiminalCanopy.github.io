# 輪つぎ / WATSUGI — 当日変更に強い交流会・席替えプランナー

2026-11-22 / ブラウザ完結・無料・登録不要 / MIT

## だれに・なぜ
小規模の異業種交流会、国際交流会、研修ワークショップ、地域の交流会を運営する人向け。実際の出席は直前に変わり、複数回の席替えでは「同じ相手ばかり」と「待機の偏り」を生みやすい。現場で**確定したラウンドを残したまま次の回だけ編成し直す**用途に絞った。

### 日本・海外の需要と競合（2026-11-22時点の公開情報）
- **日本の利用場面:** おおた国際交流センターの2026年7月11日開催「多文化クロストーク」には31人が参加し、参加者間の意見交換が行われた（[主催者レポート](https://www.ota-goca.or.jp/reports/6037/)）。[Doomoの着席ビジネス交流会](https://doomo.jp/event/seated-business)は、東京・大阪の今後の着席型交流会を告知している。これらは席替えMVPの**顧客数の証明ではない**。
- **国内競合:** [席替え先生](https://sekigaesensei.com/en) は席替え、特定のペアの分離、属性バランス等に対応。国内にはシャッフル主体のアプリもある。
- **海外競合:** [MixerSeater](https://www.mixerseater.com/) は複数回の着席ローテーションやバッジ・予定表に対応。[GroupMixer](https://groupmixer.app/) は既に部分参加・卓容量・繰り返しペア抑制等を扱う。したがって「重複回避・部分参加」自体は独自機能ではない。
- **差別化仮説:** 小規模イベント向けに「確定済みの実績 → 途中欠席・追加参加の反映 → **残りだけ**再計算 → 待機偏りと実際の交流組数を監査」を1画面で完結。外部サーバーへ名簿を送らず、匿名コードで運営できる点に価値があると仮定する。**需要の定量検証・支払意思・収益性は未検証**。

## 実装機能
- 2〜40名、1〜10卓、1卓2〜8名、1〜8ラウンドの編集。匿名コード、出欠表、定員超過の待機枠。
- 複数候補のヒューリスティック探索による席替え。ペア重複、卓訪問の偏り、待機回数の偏りを抑制。最適性は保証しない。
- **ラウンド確定・確定解除**、欠席変更後の未確定分再生成。確定済みラウンドは再計算しない（エンジン側で内容と出欠整合を再検証）。
- 新規同席ペア数・重複ペア回数・参加可能ペアに対する交流率・最多待機数、参加者ごとの巡回表。
- CSV書き出し、JSONバックアップと復元、印刷、スマートフォン表示。外部API・通信・自動保存なし。

## 使い方
`index.html`をブラウザで開く。匿名コードと卓設定を適用し、当日の各回の出欠チェックを更新。「未確定分を組み直す」→その回を確定→次の回へ。最初から14名のデモが表示される。保存が必要ならJSONをエクスポートする。

## 検証（2026-11-22）
- **Node.js `node --test engine.test.cjs`: 28/28 合格**。うち、出欠変更・卓容量・ロック履歴・JSON改竄・CSVエスケープ・500通りの固定シード条件を検証。
- **Chromium / Playwright `python browser_test.py`: 42/42 合格**。出欠変更、再計算、確定済みの不変性、Undo、CSV/JSONの入出力、XSS文字列、モバイルレイアウトを検証。ページエラー・外部HTTPリクエスト0件。
- **環境制約:** Chromium実行環境で`file://`が管理者ポリシーによりブロックされたため、テストは`index.html`に同一CSS・JSをインライン結合して`page.set_content`で操作した。通常ブラウザでの分割ファイル直接起動・現場運用・複数端末同期は未検証。ブラウザ上で長期保存する機能はない。
- イベント設計上、強制的に全参加者を毎回着席させることはできない。計画上の「交流済み」は同卓の推定であり、実際の会話を証明しない。

## プライバシー・費用
計算は端末内で完結し、ログイン・OpenAI API・外部サーバー・有料ライブラリは不要。利用者が自分でJSON/CSVをダウンロードした場合のみ情報がファイルに残る。氏名など個人情報を入力せず匿名コードを使う運用を推奨。
