# RenameRelay / 改名順序ラボ v1.0
2026-11-29 · 同一フォルダのファイル名変更順序を計画するオフラインWebアプリ。

## 対象・選定理由
制作会社、写真・動画編集者、データ移行担当者、開発者。既存名を交換・連鎖変更する場合、単純な一括改名では途中の名前が占有される。日本語の濁点（NFC/NFD）や英字の大小文字も検討対象。国内・海外の既存ツールが示す課題を根拠に選定したが、市場規模・検索数・支払意向は未測定。

## 競合・差別化仮説（2026-11-29調査）
- 日本語 Rename Wizard: 整形候補・重複回避・CSV。https://nicheworks.app/tools/rename-wizard/
- 日本語 unicode_norm: Unicode正規化の検査・変換。https://unicode-norm.guessme.info/ja/
- Microsoft PowerRename: 一括置換・プレビュー・取り消し。https://learn.microsoft.com/en-us/windows/powertoys/powerrename
- 海外 ZRename: 循環・大小文字変更の二段階処理、履歴。https://github.com/TheHolyOneZ/ZRename
- 海外 ToolSorcerer: 正規化・予約名・衝突回避の対応表。https://toolsorcerer.com/cross_platform_filename_sanitizer

差別化は任意の元名→新名対応表に対し、名前が空く順に変更し、循環だけを一時退避する最少手順の可視化と復元順序の出力。既存サービスの置き換えではなく移行レビューの補助。競合に循環処理自体があるため、その機能だけを独自性とはしない。

## 使い方・モデル
index.htmlをブラウザで開き、タブ区切りの元名/新名と変更しない名前を入力（合計最大500件）。完全一致・NFC・NFC＋小文字の比較モデルを選択、計算し、再生・JSON保存。名前だけを扱い、ファイルは読み込まない。通信や依存ライブラリなし。
新名が重複せず、固定名に衝突しない条件下、依存関係は鎖または循環。空き先を順に処理し、各循環につき一回だけ一時退避する。占有中の同一比較キーへの直接改名を禁止するモデルでは、変更件数＋循環数が下限となり、その下限を達成する。比較キーが同じで表記のみ変更する場合も循環として扱う。
OSの厳密な比較・文字制限、実ファイルの有無、権限、同時操作、入れ子パス、実際の復元は対象外。予約名等の検査は限定的。漏れのない既存名一覧が前提。実行コマンドは生成しない。JSONは入力名を含むため共有前に確認すること。

## テスト（実施済み）
- `node test.cjs`: 固定12グループ（最大規模含む）、乱数250件で独立BFSの最少手順数・順方向/逆方向の衝突なしを照合、全合格。500件の循環は501手順。
- `python test_browser.py`: Chromiumで再生、JSONダウンロード、重複・固定名衝突拒否、入力変更による無効化、390px幅、JS例外0・HTTP(S)要求0を確認。環境のfile://制限により同一HTMLをインラインで読み込んだ。要Python PlaywrightとChromium（テストでは/usr/bin/chromium）。
- 初期サンプル: 5件、全件二段階方式10手順に対し7手順（2回退避）。
- 重複確認: 直近の制作履歴、GitHub比較の先頭300ファイル（51アプリディレクトリ）、rename/リネーム/ファイル名/RenameRelayのコミット検索で同一案なし。全ブランチの全ソースは未照合。
