# 釣銭リハ / TSURISEN REHEARSAL

**現金会計が何件目で止まるかを、開店前に順番どおり試すブラウザMVP。** 無料・登録不要・依存ライブラリなし。`index.html` をブラウザで開く（または静的サーバーで配信）。外部API、秘密情報、利用者の個人情報の収集はありません。

## ターゲット・市場観察（調査日: 2026-11-22）

ターゲットは現金を扱う**マルシェ・即売会・学園祭・小規模店舗の出店者**。経済産業省は2026年3月31日、2025年の国内キャッシュレス決済**金額**比率58.0%を公表した。これは決済**件数**や「現金客42%」を意味しない。キャッシュレス化の進展後も現金対応の運用課題を想定できるが、市場規模や利用意向の直接証拠ではない。

- 国内: [ツール横丁・釣り銭準備／金種計算](https://tool-yokocho.com/tsurisen) は金種別の準備とレジ締めを扱う。[ToolkitsLab おつり計算](https://toolkitslab.com/tools/change-calculator) は単発のおつりと在庫代替案を提供。2026年11月には[BOOTH「釣り銭プランナー」](https://booth.pm/ja/items/9044439) が価格から複数試行して95%の日に足りる枚数を出す方法を案内しており、**シミュレーション自体は新規性ではない**。
- 海外: [Till Counter](https://www.tillcounter.app/) は複数通貨の金種数え、[SageBizet Cash drawer](https://sagebizet.com/features/cash-drawer) は現金残高の照合を扱う。現金の不足・過不足管理という課題は国外にも存在するが、本アプリの需要を示すものではない。
- 技術的な隣接例: [「文化祭屋台の釣銭問題をモンテカルロシミュレーション」](https://codeokiba.com/stallsimulation/) は確率的試算の先行アプローチを示す。
- 一次統計: [経済産業省「2025年のキャッシュレス決済比率を算出しました」](https://www.meti.go.jp/press/2025/03/20260331006/20260331006.html)（2026-03-31公表、2026-06-18更新）。

**選定理由・差別化仮説**: 既存の金種合計表や単発の釣銭計算と異なり、**「現金客がこの順番で来たら何人目で止まるか」**を手元の金種在庫で正確にリプレイし、その停止時点の補充案を**開店時の金種枚数に適用して再試行**できる。「事後のレジ締め」や「統計的な準備額」では把握しづらい会計の順番・金種不足の原因に焦点を当てる。ただし、同様の機能を持つ製品が全くないとは主張しない。受容性・継続率・課金可能性は未検証。

## 実装済み

- 開店時の日本円9金種（10,000/5,000/1,000/500/100/50/10/5/1円）を編集し総額算出。
- 名前・価格・支払方法を指定した取引の追加・変更・削除、上から順に会計をシミュレーション。
- 各会計で受け取った現金を在庫に入れ、**有限の金種でお釣りを構成できるか**をメモ化した探索で判定（単純な貪欲法ではない）。複数の組み合わせがあるときは最少枚数を優先。
- 最初に停止した会計を特定し、**その停止時点で必要な補充金種の組み合わせ**を計算、開店時枚数へ適用して再試行（最適開店準備の保証ではない）。
- 価格候補・客数・試行数・支払金種比重・固定シードを設定した最大300回の疑似客列テスト、成功割合と停止例の表示。
- CSV会計票（BOM付き）、JSON保存・復元、印刷、ブラウザ内自動保存、スマートフォン表示。CSV式注入と画面HTML注入への防護を実装。

## 使い方

1. `index.html` を開き、01で開店時の金種枚数を入力。
2. 02で会計の順番と金額・預かり方を入力。停止行や残金種、応急補充案が即座に更新される。
3. 03で仮定の支払比重を入力して「客列テストを実行」。結果は計算後に表示。
4. CSV/JSONを保存、または印刷。JSONから復元可。

**モデル上の限界**: 2,000円札、混合金種での支払い、カード・電子決済、両替・返金、販売数量の相関などは未対応。「ちょうど」は最少枚数の組み合わせで受け取る。シミュレーションの分布はユーザーの仮定であり、現実の会計成功率ではない。価格が支払紙幣を超える場合はより高額の紙幣へ繰り上げる。停止時の補充案を開店時に追加しても途中で使われるため成功を保証しない。会計ログはブラウザ内の試算で、実際のレジ帳簿ではない。

## テスト・再現

- `node --test engine.test.cjs` : **31/31合格**。金種・収支保存則、有限在庫での釣銭探索、貪欲法が不十分なケース、150件の参照全探索照合、400件の固定シード連続取引の保存則、テスト再現性、CSV安全性など。
- `python browser_test.py` : **40/40合格**。Chromiumで金種編集、計算結果、取引の追加・削除、応急案適用、擬似客列計算、CSV/JSONダウンロード・復元、XSS無害化、レスポンシブ表示、外部HTTP通信なし・JS例外なしを確認。`desktop.png`, `mobile.png` はテストスクリプトが生成。
- **制限**: 実行環境の管理ポリシーがブラウザの `file://` とネットワークURL直接ナビゲーションを遮断するため、ブラウザテストは配布物と同一の HTML/CSS/JS を**インライン展開**して操作。`localStorage` はテストダブルで模擬した。通常ブラウザでの静的ファイル起動・永続化や現場での現金運用は未検証。これはテスト済み操作機能と明確に区別する。
