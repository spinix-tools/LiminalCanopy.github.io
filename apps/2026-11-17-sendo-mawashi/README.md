# 鮮度まわし / SENDO MAWASHI

小さなパン・菓子店、カフェ、食品小売店向けの **ロット別期限×日販×販促シミュレーター**。登録不要、通信不要、買い切りサービス不要のWeb MVP。

## 選定理由と差別化仮説（調査：2026-11-17）

- **需要**：農林水産省が2026年6月30日に公表した2024年度推計で、日本の事業系食品ロスは**237万トン**。食品小売業48万トン、外食産業70万トン。対策への社会的需要はあるが、本MVPの顧客数・有償需要を示す数値ではない。 https://www.maff.go.jp/j/press/shokuhin/recycle/260630.html
- **国内競合**：ユニフィニティーの「食材賞味期限アプリ」は飲食店・給食施設向けに入庫・期限・使用履歴を一元管理。日本の「タベキル」は家族向けの写真登録や期限通知を提供。 https://marketplace.unifinity.co.jp/app/food-expiration-management/ / https://apps.apple.com/jp/app/id6758812623
- **海外競合**：VivaShelf は期限ロット別のFEFO・ロスレポート・オフライン機能を提供。FEFOもバーコード/日付スキャンと通知を提供。したがって「期限順に並べる」だけでは差別化しない。 https://vivashelf.com/ / https://getfefo.com/en/
- **仮説**：小規模店舗に必要なのは大規模なトレーサビリティより「**現在の日販のままなら何個余り、期限2日前の販促でどこまで減らせるか**」という意思決定を、在庫台帳と同じ画面で確認すること。日本語・ローカル完結・仮定明示の軽量設計が有効かを実利用で検証する。独自需要・競争優位は未検証。
- **既作と非重複**：時差会議・抜取検査・端材割付・釣銭・雨水・梱包・字幕・ラベル印刷・画像黒塗り・待ち列配置とは別領域。

## 主な機能

1. 商品（日販予測、単位、原価、売価）とロット（数量、期限、名称）の追加・編集・削除。
2. FEFO（期限が早いロットを優先）の7/14/21/30日予測、日別在庫グラフ、売上・欠品・期限ロス原価の集計。
3. 期限2日前〜期限当日に需要が+0〜100%増える仮想販促と現状の**差分表示**。土日の販売倍率設定。
4. 実際の販売・使用または廃棄を期限内ロットから減算、直近記録を取消。
5. ブラウザ `localStorage` に自動保存。JSONで復元、在庫CSVと予測CSVを出力。印刷対応。

## 起動・テスト

`index.html` を開くだけ。ブラウザでのローカルファイル読み込みが制限される場合は `python -m http.server 8000` からアクセス。通信ライブラリ・有料API・アカウントは不要。

```bash
node --test engine.test.cjs
python browser_test.py  # playwright + Chromiumが既に導入された環境
```

## 検証（実行環境の実測）

- Node.js 22: 単体テスト **16/16 PASS**（日付、期限、FEFO、在庫切れ、販促、実績取消、入力検証、CSV）。
- Chromium + Playwright: 操作試験 **30/30 PASS**（追加・編集・実績反映・取消・CSV/JSON・復元・レスポンシブ・XSS入力）。ネットワークナビゲーションが管理環境で制限されるため、HTML+JSをページに直接読み込み、localStorageのみ模擬。実配信・永続保存の本番検証ではない。
- 本番配信・実店舗・複数端末・ロットの現物照合・需要予測精度は未検証。

## 計算上の境界・注意

ロットの期限日はその当日まで利用できるものとして計算し、期限の種類（賞味/消費）や保管状態、衛生判断は扱いません。売上増加試算は**数量増加のみ**で、値引き額・価格弾力性・粗利・在庫補充・季節要因は計算しません。日販予測は曜日倍率以外一定、切り上げではなく四捨五入。シミュレーションは実績を変更しません。実績は同時編集や過去日への厳密な時系列整合を検証しない単一端末MVPです。JSONのバックアップは利用者自身で保管してください。食品販売可否・衛生管理・期限表示の根拠にしないでください。
