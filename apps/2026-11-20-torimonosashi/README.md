# とりものさし / TORI MONOSASHI 🐦

**制作日:** 2026-11-20（JST）｜**分野:** 野鳥観察・フィールドノート / 個人向けオフラインWeb MVP

`index.html` をブラウザで開いて使用します。`style.css`・`engine.js`・`app.js` を同じフォルダに配置してください。ビルド、登録、ログイン、API、外部CDN、有料サービスは不要です。架空のサンプル13件が最初から読み込まれます。

## 誰に、なぜ

**対象:** 日本の探鳥初心者、野鳥の会の地域サークル、身近な公園の観察ノートを付ける人。海外の個人バードウォッチャーにも共通する「前年・季節の記録は、観察時間と回数が違うとそのまま比較できない」という課題に絞ります。

**国内需要の根拠（限定的）:** 日本野鳥の会の2025-04-10公開資料では、eBird利用者は**2025-04-01時点で世界110万人、国内9400人超**、同会の会員・サポーターは約5万人と記載。2026-04-08には愛鳥週間のeBirdチェックリスト投稿キャンペーンも告知しました。既存の観察記録習慣があることを示す材料ですが、**本アプリの購入意向、利用者数、成長率ではありません**。
- https://www.wbsj.org/activity/press-releases/press-2025-04-10/
- https://www.wbsj.org/activity/press-releases/press-2026-04-08/

**競合:** 国内・日本語対応の[eBird Japan](https://www.wbsj.org/activity/conservation/ebird/about_ebird/)はチェックリスト投稿・種リスト・地域の出現頻度、海外の[Birda](https://birda.org/features/logging/)は観察セッション・種数や個体数・ライフリスト、英国[BTO BirdTrack](https://www.bto.org/get-involved/volunteer/projects/birdtrack/taking-part/adding-records)は完全記録を含む市民科学の観察記録を提供します。**単に「記録」「頻度」「完全なチェックリスト」の機能が新規だとは主張しません。** eBirdの地域別頻度バーは完全チェックリストのうち記録された割合であるため、方法的な先行例でもあります。

**差別化仮説:** 位置情報・アカウント・データ共有を不要とし、同一人物が手入力した**2期間の「完全記録数・出会った回数・観察時間・羽数/時・Wilson区間」**を一画面で比較し、完全記録のない期間を「0%」ではなく「未算出」と表示する。「数字が減った／増えた」と早合点しないための、プライベートな振り返りツールという訴求です。既存サービスへの優位性・ヒット可能性・収益性は未検証です。

## 実装済みの操作

- 日付、場所の**自由記述ラベル**（正確な住所/GPS不要）、観察分数、鳥名と羽数の複数行入力、完全記録／部分記録、鳥がゼロだった観察の登録
- ログの一覧、編集、削除、完全記録の切替、任意の鳥と場所・2期間の比較
- **出現率**＝完全記録のうち対象種が記録された回数 ÷ 完全記録数、**羽数/時**＝対象種の記録合計 ÷ 完全記録の総観察時間。部分記録は比較に入れない
- Wilsonの95%参考区間、観察時間差・サンプル数不足の警告、月別出現率SVGグラフ
- JSONバックアップ／復元、CSVログ出力（数式注入対策つき）、SVG保存、印刷、localStorageへの端末内自動保存
- 入力サンプル、レスポンシブ表示、外部通信・アクセス解析なし

**注意:** 羽数は別々の観察で同じ個体を重複計数し得ます。観察時間で割っても「個体数」「密度」「個体数の増減」は推定できません。観察者、時刻、季節、天候、場所の違い、検出しやすさ、同じチェックリスト間の独立性を制御しません。Wilson区間も独立試行を仮定した記述的参考値です。地域・現地への公開や市民科学データ提出の代替にはしないでください。
