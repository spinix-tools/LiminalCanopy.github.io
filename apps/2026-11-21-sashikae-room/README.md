# 差し替え照合室 / SASHIKAE ROOM

2026-11-21 / 個人制作MVP / MIT / サーバー・API・アカウント登録なし

## 誰の何を解くか

地域劇団、学生演劇、朗読劇、ワークショップの演出助手・俳優が対象。稽古中に台本が改訂された際、**役ごとに差し替えられた台詞**と、**本人の台詞は変わっていないが直前の相手の台詞（受けのきっかけ）が変わった場所**を、ブラウザで確認・印刷できるようにする。

## 選定根拠 / 競合

- **国内需要の参考**：日本劇団協議会の2026年7月3日公開「演劇団体調査2025」には全国800余の団体から回答があった。劇団の活動基盤は存在するが、**差分アプリへの支払意思を証明する数値ではない**。[日本劇団協議会](https://gekidankyo.or.jp/news/news-3054/)
- **国内競合**：iOSアプリ「ハレ舞台」は縦書き台本、PDF閲覧、ページメモを提供する。役ごとの改訂通知を主機能とするとは確認できなかった。[App Store](https://apps.apple.com/jp/app/%E3%83%8F%E3%83%AC%E8%88%9E%E5%8F%B0/id6825608432)
- **海外競合**：Final Draftの *Revision Mode* は改訂箇所・改訂ページ色を管理し、2025年2月19日更新のヘルプで説明している。[Final Draft](https://kb.finaldraft.com/hc/en-us/articles/27813588722708-How-do-I-use-Revision-Mode) またScripticoは役別の台詞読み合わせ・キュー練習を提供。[Scriptico](https://scriptico.app/en/run-lines-app)

**差別化仮説**：総合脚本エディタでも暗記支援でもなく、二つの日本語プレーンテキスト稿から「誰が何を差し替え、誰が受けを再確認するか」を即座に出す軽量な配布前チェックに価値がある。競合が強く、需要・差別化・収益性はいずれも未検証。まず劇団3〜5団体による実際の変更稿の確認時間を測るのが適切。

## 操作と機能

1. `index.html` をブラウザで開く。依存パッケージもサーバーも不要。サンプルの旧稿・新稿が最初から読み込まれる。
2. `# 第一場` のような場面見出し、`葵：セリフ` のような「役名：台詞」を入力（コロンは全角半角どちらでも可）。それ以外の非空行はト書きとして比較する。`.txt` 読込可。
3. 「差分を照合する」または Ctrl/Cmd+Enter。追加・削除・書換を検出し、役で絞り込む。
4. 変更のなかった台詞についても、**直前の相手の台詞が旧稿と新稿で異なる**場合に「受けの確認候補」を表示する。
5. 絞込済み確認票をCSV・印刷／PDFで出力。台本の両稿をJSONに書き出し／読み込み可能。「端末に保存」は明示操作した場合のみブラウザのlocalStorageへ保存する。

台本のアップロード、解析API、音声収録、個人情報入力フォーム、広告、課金はない。取り込んだ台本はページ内で処理する。ブラウザ内の保存や手元のJSONファイルの管理には注意。

## アルゴリズムと限界

- 場面名と**同名場面の出現順**で対応付け、各場面で編集距離型の順序アラインメントを実行。役名が同じ場合は書換候補として優先し、異なる役への移動は追加・削除として扱う。NFC正規化と前後空白除去を行う。台本の行順が基準。
- 受け確認は「一致した新稿の台詞」に対する旧稿／新稿の直前の対話行を比較するもの。**実際のキュー・演出意図・稽古上の影響を証明しない**。ト書きや同一話者の直前台詞変化は受け警告に含めない。
- 場面名変更・大規模入替・繰り返しの台詞・同役による全く別の台詞は誤対応が起こる。自動検出した「書換」と「追加／削除」の境界は要目視確認。各稿9万文字、台詞・ト書き600行まで。PDF/Word取込、音声比較、複数版履歴は未実装。
