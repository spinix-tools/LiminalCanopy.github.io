# おつり予報 / OTSURI YOHO

**現金販売イベントの釣銭不足を、金種別の開始在庫と客の支払傾向から試算するオフラインWebアプリ。**

- 実行方法: `index.html` をブラウザで開く。依存ライブラリ・API・ビルド手順なし。
- 主な機能: 商品名・単価・売れ行き重み編集 / 来客数・2点買い確率・支払傾向 / 10金種の開店釣銭編集 / シード固定の反復シミュレーション / 不足件数・90%点・平均成立売上・取引例 / 予算上限付き金種追加の近似案 / 単発のおつり計算 / JSON設定保存・読込 / CSVレポート / 印刷 / 端末内localStorage保存。
- 対象: 日本のマルシェ、学園祭、フリーマーケット、同人即売会、その他小規模現金売り場の出店者・運営者。

## 選定理由と競合（2026-11-18時点の公開情報）

- 国内: 経済産業省は2026-03-31に2025年の**キャッシュレス決済比率（国内指標）58.0%**と公表。金額ベースの全国指標であり、イベントの現金利用率や本製品への需要を直接示さない。 https://www.meti.go.jp/press/2025/03/20260331006/20260331006.html
- 海外: USDA農業マーケティング局は2025-08-06時点の案内で、米国内**8,600超**のファーマーズマーケットをディレクトリで扱うと記載。これは販売現場の規模を示す周辺指標であり、釣銭アプリ需要ではない。 https://content.govdelivery.com/accounts/USDAAMS/bulletins/3ebc6a9
- 国内競合: [お釣り電卓](https://apps.apple.com/jp/app/%E3%81%8A%E9%87%A3%E3%82%8A-%E9%9B%BB%E5%8D%93/id367338685) は会計時の釣銭内訳、[即売レジ](https://apps.apple.com/jp/app/%E5%8D%B3%E5%A3%B2%E3%83%AC%E3%82%B8/id730021836) は販売記録・釣銭計算を提供。
- 海外競合: [Till Counter](https://www.tillcounter.app/) は手元現金の金種別集計、[Change Counter](https://www.changecounter.org/) はレジ現金集計とCSVレポートを提供。
- **差別化仮説**: 現場でのおつり計算より一歩前の「出店前」に焦点を当て、商品別売れ行きと支払傾向から不足件数の分布を見せ、追加する金種の案を同じ画面で出す。オフライン、日本円10金種、登録不要、端末内保存。競合調査は網羅的ではなく独占的な機能だとは主張しない。

## 計算の仕様と限界

- 各取引では、重みに従い商品1点を選び、設定確率で追加1点を選ぶ。支払は「ちょうど / 次の1,000円 / 次の5,000円 / 次の10,000円」を選択。ちょうど払いの持参金種や複数枚支払いは、額面の貪欲分解で単純化。
- 開店在庫に受取金を加えた後、利用できる金種に制約されたおつりの組合せを探索。不足なら取引不成立とし、在庫・売上に反映しない。**実際の現金決済の予測ではなく、設定した仮定のもとでのシナリオ比較**。
- 反復回数ごとに同じ初期在庫から再開、シードで再現可能。予算内の推奨は金種パックの逐次・貪欲な近似探索。全金種の最適組合せや不足ゼロを保証しない。来場数、商品重み、支払習慣、銀行両替手数料、5円未満の価格差、現場オペレーション等に結果は依存。
- ブラウザ外送信、第三者ライブラリ、追跡タグ、決済サービス、ユーザー登録はない。現地の現金管理・帳簿や税務資料には使わないでください。

- **環境制約**: 管理環境のChromiumは `file://` 直接遷移を `ERR_BLOCKED_BY_ADMINISTRATOR` で遮断。テストは**同じHTML/CSS/JSソースをabout:blankへインライン化**し、`localStorage` をメモリ模擬して実施。通常ブラウザでの直接ファイル起動、実配信、実機印刷、ブラウザ本物の保存永続性はこの環境では未検証。実売上との予測精度も未検証。
