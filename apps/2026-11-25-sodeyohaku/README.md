# 袖余白 / SLEEVE MARGIN
2026-11-25 | 日本語・ブラウザ完結MVP

**対象**：ボードゲーム愛好家、カードゲームのコレクター、小規模ゲーム制作者。スリーブ変更や拡張追加で既存収納が足りなくなる場合に、実測から変更する束を選ぶ。

**市場・競合（2026-11-25確認）**：国内の[スリーブイン](https://sleeve-in.com/)は対応サイズ・余白・袋数を表示。[ゲームマーケットの商品例](https://www.gamemarket.jp/game/184064)はスリーブ装着後に小箱が浮く問題への対策。海外の[BoardGameGeek](https://boardgamegeek.com/thread/3137048/sleeving-your-games-just-got-easier)は2023年に約7,000作品の対応情報を統合、[Sleeve Kings](https://sleevekings.com/collections/sleeves-by-skus%20)は1万超の作品・拡張の対応情報を提供。[Card Fit Lab](https://cardfitlab.com/)や[BoardFit Atlas](https://boardfitatlas.com/tools/sleeve-storage-volume-calculator/)は収納適合・厚さ推定を提供する。市場規模や購買意欲は未測定。

**差別化仮説**：単独の束の適合可否ではなく、同一収納列の複数束について、現状維持か変更かを一括選択する。追加予定枚数・予約余白・実測厚・ユーザー指定優先度を扱い、箱を買い替えずに済む案を提示する。既存機能との差は調査範囲での仮説。初期検証は愛好家に実測入力と提案の有用性を試してもらう。

**使い方**：index.html をブラウザで直接開く。1つの収納列の内寸・予約余白を入力。1行9列のタブ区切りで束名、現在枚数、追加枚数、実測枚数、現状厚、変更後厚、装着後最大外幅・外高、優先度を登録（最大16束）。サンプルから編集可能。計算後、推奨案と比較、CSV、印刷を利用できる。

**計算**：0.1mm整数単位で、各束厚 = ceil(サンプル厚×合計枚数÷実測枚数×安全係数)。外寸は両仕様の大きい方で保守的に判定。全2^n候補のうち奥行制約を満たすものを優先度合計最大→変更束数最大→使用奥行最小で選ぶ。束内の仕様混在はしない。サンプルは全現状46.2mm、全変更66.2mm、使用可能57.0mm、最適55.7mm（2束、優先度11）。

**検証**：`node test.cjs` 固定10/10、独立再帰列挙400/400、16束65,536候補合格。`python browser_test.py`（Playwright、Chromium `/usr/bin/chromium`）で初期計算・CSV実ダウンロード・入力変更時の無効化・外寸超過・不正値・奥行解なし・リセット・390px幅、JS例外0・外部HTTP要求0を確認。環境の file URL 制限により HTML をインライン読み込み。実機印刷未実施。

**制約**：直線1列・固定方向、両仕様で共通の最大外寸を使う保守的モデル。空気・変形・開口・取り出し・スリーブ内寸は実物確認が必要。優先度は保護性能ではない。収益性・実需要・実物適合は未検証。外部API・課金・追跡・永続保存なし。既存mainに変更しない。
