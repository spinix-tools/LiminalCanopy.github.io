# 端材バンク / HAZAI BANK

**1Dの長物カット計画と、端材の次回在庫化を一画面で行う、登録不要・ローカル完結のWebアプリ。** 2026-11-17制作。

## 誰に / なぜ

**ターゲット:** DIY愛好家、小規模木工房、アルミ・パイプ加工の個人工房。一本ずつ寸法を測り、規格材と前回の端材を混ぜて計画する場面。

**日本市場の参考材料:** 経産省の商業動態統計に基づく2026年8月のホームセンターのDIY用具・素材売上高は640億円、前年同月比+3.9%（流通ニュース、2026-09-30）。ただしこれはアプリの市場規模でも課金需要でもない。 [記事](https://www.ryutsuu.biz/sales/s093043.html)

**競合:** 日本のiOS「CutPlan 板取り最適化・木取り図」は刃厚を含む1D/2Dカットに対応（[App Store](https://apps.apple.com/jp/app/cutplan-%E6%9D%BF%E5%8F%96%E3%82%8A%E6%9C%80%E9%81%A9%E5%8C%96-%E6%9C%A8%E5%8F%96%E3%82%8A%E5%9B%B3/id6792293888)）。海外の [Cut Wizard](https://cut-wizard.com/) は1D割付・印刷・材料管理、[CutWize](https://cutwize.com/) はカット確認と端材再在庫化まで実装済み、[NestSolver](https://nestsolver.com/optimize) は再利用端材とスクラップの区別に対応。**「端材トラッキングが他社にない」という主張はできない。**

**差別化仮説:** 日本語の短いフォームで、作業前の計画（在庫を減らさない）と作業後の明示的な在庫確定を区別する。登録不要、クラウド不要、端材を優先して割付、JSONで持ち出す。軽量なDIY用途に絞ることで受容されるか検証する。需要・収益性・継続利用は未検証。

## 実装した機能

- 規格材・端材、部材の登録・編集・削除（長さmmと本数）
- 刃幅（各部材につき1回分を控除）・両端の端切り・端材再利用下限の指定
- 長い部材から割り付けるヒューリスティック、既開封材の残余優先／新規開封時は端材優先、未割付の警告
- 割付図、使用本数、再利用候補、材料歩留まり、予測スクラップ
- 実際にカットした後でだけ使用材を減算し、再利用可能な端材を在庫へ反映（直前の確定は取消可能）
- localStorageによる端末内保存、JSONバックアップ／復元、CSV出力、印刷、スマホ表示

すべて静的ファイルで稼働。外部JavaScript、Cookie、アナリティクス、ネットワーク通信、OpenAI API、ログインなし。個人情報・秘密情報は要求しない。

## 起動・テスト

同じフォルダに `index.html`, `engine.js`, `app.js` を置き、`index.html` を開く。最新ブラウザ推奨。

```bash
node --test engine.test.cjs
python browser_test.py  # playwright と /usr/bin/chromium が必要
```

**検証結果（2026-11-17）:** Nodeロジック単体 **21/21合格**（制約・境界値・在庫計上・CSV・乱数固定80ケースなど）。ChromiumのUI操作 **24/24合格**（登録／編集／削除／設定再計算／JSON・CSV出力／模擬永続化／在庫確定・取消／モバイル幅）。JS例外なし、画面画像 `desktop.png`, `mobile.png` を同梱。

**制限:** 実行環境の管理者ポリシーにより `file://` へのブラウザ直接遷移が拒否されたため、ブラウザ試験はHTMLにローカルJSをインライン化して `page.set_content` で実行。localStorageはメモリ内の代替で模擬。したがって実端末でのストレージ持続性・印刷実寸・材料加工精度・GitHub Pagesでの動作は未検証。

## 計算上の制限・注意

1次元、単一材質・同一断面の長物のみ。ノコ刃の消費を各部材に1回分必ず加える保守的なモデルで、切り順、端材端面の状態、材の反り・節、クランプの余裕、交換費用、価格・角度・木目は計算しません。割付はヒューリスティックであり**最適解を保証しません**。端材長は加工前の予測値であり、物理的な実測値ではありません。確定前に実物を測定し、違えば在庫編集で訂正してください。作業安全に関する専門判断の代わりにはなりません。保存上限は在庫120本、部材300個。
