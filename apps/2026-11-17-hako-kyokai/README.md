# ハコ境界 / HAKO KYOKAI

**2026-11-17 / hourly-app-lab** — 箱に「入る」と、配送サイズに「収まる」を分けて検討する、登録不要・オフライン動作の梱包MVP。

## 対象と選定理由

対象は小規模EC、フリマ出品、手作り商品の発送担当者。梱包は内寸の収容だけでなく、段ボール厚みで増える外寸、商品を守る余白、重量、配送サービスの規格が絡む。日本のEC梱包コスト解説では箱のサイズ区分が費用に影響することが指摘される。ヤマト運輸の案内では宅急便は三辺合計に応じて60〜200サイズの区分がある。ただし、サイズ区分は重量・最長辺等の条件もあり、**本アプリは三辺の合計値だけを参考表示**する。

## 日本・海外競合（2026-11-17 確認）

- 日本：iOSアプリ **TETRA**（検索結果に **PACKWISE** とも表示される同一App Store ID）は商品・箱登録、3D配置、梱包順序・箱数提案が可能。箱の配置計算そのものは独自ではない。
- 海外：**CartonPilot** は3D bin-packingをAPIで提供し、重量・破損しやすさ・積み重ね規則も扱う。**DimPack3D** はブラウザでの3D詰め込み・出力を提供。
- 参考：日本のEC物流実務記事で箱サイズ区分と梱包資材費・送料の関係を確認。

**差別化仮説**：計算精度を競うのではなく、個々の品目周囲の予約余白、箱の内寸と壁厚から求める外寸、その3辺合計の区分境界を一画面で比較し、梱包作業用の位置一覧まで印刷できる軽量な日本語ツールとして使われる可能性がある。競合も非常に強く、顧客獲得・収益性は未検証。

## 実装したもの

- 商品の寸法・数量・重量・回転条件（自由／上下固定／固定）を追加・編集・削除
- 箱の内寸・壁厚・自重を追加・編集・削除
- 予約余白を含めた3次元直方体の近似配置（重なりを拒否し、底面が全面支持されるか確認）
- 箱別の配置可否・不足商品数、外寸3辺合計、体積利用率、重量の比較
- 斜投影SVGでの配置図、位置・占有寸法の順序付き一覧、CSV、印刷
- localStorage保存、JSONエクスポート／インポート、サンプル初期化
- ネットワーク通信、外部SDK、ログイン、個人情報収集、課金なし

### 操作方法

`index.html` をブラウザで開く。`engine.js` と `app.js` は同じフォルダに置く。商品を追加して箱の内寸を設定すると自動計算される。箱候補をクリックすると図と一覧が更新される。余白スライダーで緩衝材を確保する。CSVで手順を保存できる。

### アルゴリズム上の制限

これは最適解を保証しないヒューリスティック。直方体・軸平行・非変形品だけに対応し、底面の支持領域を幾何検証するが、実物の強度・落下・重心・緩衝材の性能・押しつぶれ・箱の耐荷重は検証できない。入らないという表示は「この探索方法で配置できなかった」場合を含む。側面がつかえても実物で入る、逆に図上では収まっても破損する可能性がある。**配送会社の料金、重量区分、最長辺・形状制約を判定しない**。容量を超える荷物の配送にこの表示を使わないこと。
